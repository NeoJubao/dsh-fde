# fde-pilot · 试点设计与成功指标

> 定位：把方案收敛成**一个可验证的闭环**：范围、成功指标、里程碑、退出条件、资源与合规前置。试点是证明价值的最小单元，不是缩小版全面交付。
> 铁律：**指标不可测就不写**；客户没有书面确认的试点范围和成功指标，不算进入 pilot。`pilot` 门禁人工项 `pilot_scope` 要求 **Pilot Charter 六项齐全**、缺一不可。

## Pilot Charter 六项（缺一不可）

| # | 项 | 要求 | 不满足的后果 |
|---|---|---|---|
| 1 | 时间门限 | 首次数据/系统集成 ≤14 天；生产上线 ≤90 天；**失败撤出 ≤120 天**（客户可接受的最小损失窗口） | 试点变无限期驻场 |
| 2 | 基线 | 上线前测得现状数值与口径（耗时/错误率/处理量/成本），有数据来源与日期 | 无法证明提升，验收必争议 |
| 3 | 成功指标 | 可量化 + 口径 + 数据源 + 验收人（每个指标四件套） | 指标不可测 → 不启动 |
| 4 | 验收口径 | 达标判定规则、测量窗口、谁签字；含「部分达标」如何处理 | 尾款/转正无依据 |
| 5 | 失败退出条件 | 触发条件（指标/时间/成本/合规）+ 撤出步骤 + 已发生费用结算 | 客户不敢开始、我方不敢停 |
| 6 | 转正式判据 | 达标后转交付/采购的条件、流程与时限；免费/低价试点必须写 | 试点免费无限延长（Palantir 教训：试点是获客成本，不是收入） |


## 一、触发时机

- 「先做个试点/POC」「怎么定义成功」「先跑一个场景给客户看」。
- 客户进入 `pilot` 阶段，门禁缺试点方案、成功指标或客户确认。
- 试点跑完要复盘：达标/未达标、是否扩展到交付。
- 「试点跑完了，能不能交付？」→ 按成功指标与退出条件逐项判定，给转交付建议。
- 「Charter 还缺哪几项」→ 用上表六项逐条对照，缺项不进 pilot。
- 不触发：写正式方案（`fde-solution`）、实施交付（`fde-delivery`）。

## 二、输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 已定稿方案 / 合作地图 | 是 | 试点范围必须落在方案边界内 |
| 客户痛点与 KPI 假设 | 是 | 决定成功指标，需客户认可的口径 |
| 可用数据与环境 | 是 | 数据能否出域、内网/外网、谁提供 |
| 客户侧对接人与预算口径 | 是 | 谁配合、谁验收、资源上限 |
| 时间窗口 | 是 | 试点起止与必须避开的节点（汛期/财年/审计） |

## 三、执行步骤（逐条可检查）

1. **收敛试点范围**：只选 **1 个场景**、1 个闭环；写「本次不做清单」，把方案里其余场景明确排除。检查：范围外清单 ≥3 条，避免被当成全面交付。
2. **定义成功指标**：每项给「基线值 / 目标值 / 测量口径 / 数据来源 / 谁验」，可量化的优先（工时、通过率、成本、响应时长）。检查：没有不可测指标；没有用「提升体验」这类表述凑数。
3. **设里程碑与决策门**：起止日期、阶段成果、继续/调整/终止条件。检查：每个里程碑有可交付物与验收人。
4. **资源与责任**：客户侧配合人（姓名/部门/职责）、我方交付物、双方不做什么。检查：责任矩阵里没有空白项。
5. **合规与数据前置**：数据出域边界、授权文件、保密要求、驻场条件；涉密场景先确认资质与通道。检查：数据合规项有结论（可行/不可行/待确认），不是「应该可以」。
6. **写试点方案**：目标 / 范围（含不做清单）/ **Pilot Charter 六项**（时间门限、基线、指标、验收、退出、转正）/ 里程碑 / 责任 / 数据与合规 / 风险。检查：Charter 六项逐项落笔，缺项写明原因且不允许启动。
7. **客户确认**：把「范围 + 成功指标」单独整理成一页确认件，由人拿去确认；确认结果写回 `pilot/客户确认.md`（日期、确认人、口径）。检查：没有确认就不把 `pilot_scope` 当已过。
8. **回报**：`fde_item {action:'report', kind:'ready', text:≤300字, artifacts:[…]}`；门禁 `pilot` 的人工项 `pilot_scope` 由人在面板确认。检查：未调用 move 推进阶段。

9. **试点中纪律**：每周只更新指标与风险，不临时加范围；新需求记变更候选，试点结束再评估。检查：试点期间的变更都有记录。

## 四、产物与路径

| 产物 | 路径 | 命名规则 |
|---|---|---|
| 试点方案 | `research/<客户>/pilot/试点方案.md` | 含范围、不做清单、Pilot Charter 六项、里程碑 |
| 指标定义表 | `research/<客户>/pilot/成功指标.md` | 基线/目标/口径/来源/验收人 |
| 客户确认 | `research/<客户>/pilot/客户确认.md` | 日期 + 确认人 + 确认口径 |
| 试点复盘 | `research/<客户>/pilot/试点复盘.md` | 达标情况、偏差、转交付建议 |

## 五、边界（不做什么）

- 不承诺资源、价格、工期；客户没确认的范围不写成已达成。
- 不把试点写成全面交付，不用试点结论推导全公司成效。
- 不跳过数据合规与保密前置；资质未确认不安排现场。
- 不虚报指标：基线没有就写「未取得基线」，目标改成相对口径并注明。
- 不接受无期限、无转正判据的免费试点；试点超 120 天未转正则按退出条件处理。
- 不自行宣布试点成功或失败——结论要证据，由人拍板。
- 不用试点数据推断其他场景；不拿未验证结论去写方案成效。
