# fde-delivery · 实施、验收与风险登记

> 定位：把试点结论变成可验收的交付：实施计划（WBS/里程碑/接口）、验收清单（可测项）、风险登记（概率/影响/缓解/owner）、变更控制。交付阶段的事实来源是**客户卷里的计划与清单**，不是会话里的口头约定。
> 铁律：**agent 不自行标记验收完成**；范围变更必须走确认并留痕。

## 一、触发时机

- 「开始实施」「排个交付计划」「准备验收」「这个风险要记一下」。
- 客户进入 `delivery` 阶段，门禁缺验收清单、里程碑或风险登记。
- 交付中范围变化、客户换对接人、上线延期、验收争议。
- 「客户说范围要加、时间不变」→ 走变更记录并给影响评估，不口头答应。
- 交付报告 / 验收总结是长文（≥5 节）→ 另出一页纸（brief，加载 `longdoc-brief` 技能）。
- 不触发：试点设计（`fde-pilot`）、采用与扩展（`fde-adoption`）。

## 二、输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 试点结论 / 方案定稿 | 是 | 交付范围只取已确认部分 |
| 合同或立项范围 | 是 | 范围、工期、验收标准的依据 |
| 客户侧接口人与决策人 | 是 | 谁对接、谁签字、谁协调资源 |
| 里程碑与依赖 | 是 | 含客户侧前置条件（数据、环境、审批） |
| 风险与问题清单 | 否 | 已有登记则在其上更新，不重建 |

## 三、执行步骤（逐条可检查）

1. **锁定交付范围**：从合同/立项/方案中摘出范围与「不在范围内」清单；范围外需求一律走变更。检查：范围清单与合同一致，越界项有记录。
2. **写实施计划**：WBS（任务/负责人/起止/依赖）、里程碑、双方接口人、客户前置条件、沟通节奏。检查：每个里程碑有可交付物与验收人，没有悬空依赖。
3. **写验收清单**：逐项「验收标准 / 测试或演示方法 / 证据形式 / 验收人」。检查：没有不可测的验收项；不把「功能已部署」当验收通过。
4. **建风险登记**：风险描述 / 概率 / 影响 / 缓解动作 / owner / 复查日期。检查：高风险都有缓解动作与复查日期。
5. **变更控制**：范围、工期、费用、验收口径变更一律记录变更单（原因、影响、批准人、日期），并同步更新计划与清单。检查：没有口头变更直接进实施。
6. **周报节奏**：按 item report 或周会节奏更新进度（完成/进行中/受阻），受阻项生成注意力给负责人。检查：每个受阻项有明确「等谁/等什么/何时催」。
7. **交付物落盘**：计划、清单、风险登记、会议纪要按客户卷归档；对外交付件按 `methods/05` 走，**人确认后才生成**。长文（≥5 节）另出 `delivery/exports/交付-brief.html`（阅读版）与 `交付-brief-传阅版.html`（传阅版）。检查：md 是唯一事实来源，导出件不手改；brief 与长文一致。
8. **收尾与回报**：交付完成后整理验收证据与遗留项清单 → `fde_item {action:'report', kind:'ready'}`；`delivery` 门禁人工项（`acceptance` / `milestones` / `risks`）由人确认。检查：agent 没有自行标记验收完成或归档客户。

9. **交付物一致性**：计划/清单/风险登记三份文件交叉引用一致（同一里程碑名、同一验收人）。检查：三份文件互引无冲突。

## 五、边界（不做什么）

- 不自行标记交付/验收完成，不改客户签字件，不替客户写验收结论。
- 不擅自扩大范围、不答应合同外需求；变更必须留痕并经人批准。
- 不删除历史版本与历史风险项；关闭风险要写关闭依据。
- 不把内部问题清单直接发给客户；对外沟通件由人确认后发出。
- 不主动导出正式文档；不覆盖客户卷中的定稿文件（只追加或新版本）。
- 不在客户群里直接承诺；对外口径先与人确认。
