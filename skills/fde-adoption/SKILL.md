# fde-adoption · 采用、价值证明与扩展

> 定位：交付验收不等于被采用。本阶段回答三个问题：**有没有人在用（使用证据）→ 有没有价值（价值证明）→ 能不能扩展（扩展地图）**。
> 铁律：证据 A/B/C 分级；估算不能写成实测；没有客户授权的数据不采集、不带走。

## 一、触发时机

- 「客户用起来了吗」「怎么证明有效果」「做培训」「下一步还能做什么」。
- 客户进入 `adoption` 阶段，门禁缺使用证据、培训记录或扩展地图。
- 准备续约/扩展/新场景立项，需要价值材料支撑。
- 「这个客户能不能续约/扩场景」→ 用价值证明 + 扩展地图给建议，不替客户决策。
- 不触发：实施与验收（`fde-delivery`）、复盘方法沉淀（`fde-harvest`）。

## 二、输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 交付验收结论 | 是 | 用了什么、谁在用、边界在哪 |
| 使用数据 | 是 | 系统日志/工单/访谈；须客户授权 |
| 客户组织与考核 | 是 | 谁考核、看什么指标、向谁汇报 |
| 培训对象与时间 | 否 | 岗位、人数、可用时段 |
| 下一阶段业务方向 | 否 | 决定扩展地图分组 |

## 三、执行步骤（逐条可检查）

1. **写采用指标**：使用率 / 场景覆盖 / 用户数 / 任务量 / 节省工时 / 缩短周期，每项给「口径 + 数据来源 + 采集频率 + 谁提供」。检查：没有口径不明的指标。
2. **做培训**：对象分层（业务用户/管理员/领导层）、内容与考核方式、时间安排；培训后收集签到与考核结果。检查：培训记录含日期、对象、人数、考核结果。
3. **收使用证据（A/B/C）**：A 系统导出数据或客户签字确认；B 访谈与内部转述（标注）；C 仅线索。检查：每条证据有级别与取得方式，C 级不进价值结论。
4. **写价值证明**：基线 → 现状 → 变化量 → 计算口径 → 局限。不要用单点数据推全周期；估算与实测分开列。检查：每个数字可回算，标「计算值」。
5. **画扩展地图**：按客户业务方向分组，每组写「下一批场景 / 依赖前提 / 卡点 / 推荐优先级」；明确本次不扩展的部分。检查：扩展项都有可检查结果与卡点，没有「全面推广」这种空话。
6. **更新客户档案**：把采用状态、关键用户、价值证据索引写回客户卷与 board 时间线；干系人变动同步。检查：board 的 `stakeholders` 与客户卷一致。
7. **回报**：`fde_item {action:'report', kind:'ready', text:≤300字, artifacts:[…]}`；`adoption` 门禁人工项（`usage_evidence` / `training` / `expansion_map`）由人确认。检查：没有自行推进阶段。

9. **季度回看**：按季度重算核心指标，与基线对比；趋势下降必须写原因（改口径/使用下降/数据缺失）。检查：季度记录有对比与原因。

## 四、产物与路径

| 产物 | 路径 | 命名规则 |
|---|---|---|
| 价值证明 | `research/<客户>/adoption/价值证明.md` | 基线/现状/变化/口径/局限 |
| 使用证据 | `research/<客户>/adoption/使用证据/` | 按来源命名，脱敏后入卷 |
| 培训记录 | `research/<客户>/adoption/培训记录.md` | 对象/内容/人数/考核 |
| 扩展地图 | `research/<客户>/adoption/扩展地图.md` | 按客户业务方向分组 |

## 五、边界（不做什么）

- 不把估算写成实测，不用单点数据推全局成效，不删不利数据。
- 不采集未授权的数据；客户内部数据不出客户环境，脱敏后才能进插件仓案例。
- 不替客户对外宣传、不写客户不允许公开的案例与名称。
- 不承诺下一阶段预算、资源与结果；扩展地图是建议，不是承诺。
- 不自行标记采用完成；采用与否由客户行为和人的判断共同决定。
- 不把培训签到人数当使用证据（培训 ≠ 使用）。
- 不使用未授权的个人数据做使用分析。
