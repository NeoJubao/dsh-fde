# fde-harvest · 复盘与方法沉淀

> 定位：把一次经历变成**下次能机械执行的东西**：复盘四问 → Harness 反馈六类 → 进方法/坑卡/规则。规则承载优先级：复盘文字 < playbook/runbook < hook/自动检查。
> 铁律：脱敏——客户真名、金额、人名、涉密细节不进方法库；复盘先写事实，再写判断。

## 一、触发时机

- 「复盘一下这次会面/交付/事故」「这次哪里做错了」。
- 项目收尾、阶段卡点反复出现、同一个坑第二次出现。
- 要把经验写进 `reference/雷区清单.md`、`methods/` 或 `docs/retros/`。
- 要向 Harness 提改进（工具缺陷、权限护栏、信息获取方式）。
- 「同一个错第二次出现了」→ 直接走坑卡流程，并提 hook/自动检查建议。
- 不触发：普通进度汇报（用 item report）、客户卷事实记录（`fde-delivery`）。

## 二、输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 事件与时间线 | 是 | 发生了什么，按时间顺序，先不带评价 |
| 证据 | 是 | 文件路径、board timeline、report、消息记录 |
| 影响 | 是 | 谁受影响、多大、多久 |
| 已采取动作 | 否 | 当时怎么处理的、临时补丁是什么 |
| 相关方法/规则 | 否 | 这次违背或暴露了哪条已有规则 |

## 三、执行步骤（逐条可检查）

1. **定范围**：单事件复盘 / 项目复盘 / 阶段复盘；明确不追责、只追根因。检查：复盘范围与时间边界写在标题下。
2. **写事实时间线**：按时间列事实，不带评价；标注来源（文件/会话/timeline）。检查：每条事实有出处，没有「大概/可能」。
3. **问为什么**：当时的判断与依据（包括当时不知道的信息）；根因往环境与规则层面问，不停在「某人粗心」。检查：根因至少一层是规则/工具/环境问题，不是纯个人失误。
4. **写下次怎么做**：行动 / 负责人 / 截止 / 状态 四列表；能机械执行的优先做成检查项或 hook（如 health-check 增加一条）。检查：每个行动可验证，没有「加强沟通」这类不可检查项。
5. **填 Harness 反馈六类**：导航 / 自动检查 / 规则与审查 / 权限与护栏 / 工具与开销 / 信息获取，每类写「这次的问题 → 改哪里 → 状态」；「改哪里」必须能写出具体文件或命令。检查：六类逐类过一遍，空的写「本次无」，不省略分类。
6. **决定沉淀位置**：只对本客户有用 → 客户卷复盘；跨客户可复用 → 插件仓 `docs/retros/`；经过验证要变成规则 → 提修改建议给 `reference/雷区清单.md` / `methods/`（由人审后合入）。检查：判断依据写明（「会不会因为改代码而需要跟着改」）。
7. **脱敏检查**：客户真名 → 「某集团」；金额/人名/项目名/涉密信息删除；案例保留结构与教训。检查：方法库文本里 grep 不到客户真名。
8. **落盘与回报**：用 `fde_harvest` 工具写草稿（工具只写 `research/.fde/drafts/`，可回滚；发布到 `docs/retros/` 或客户卷由人审后执行），再 `fde_item {action:'report'}`；同一坑出现两次，明确建议起草 hook 或加自动检查。检查：草稿路径存在，未直接改已发布规则文档。

9. **规则落地跟踪**：把「建议改哪里」转成待办（谁、何时、状态），一周后回看是否真的改；没改的写原因。检查：每条建议有跟进状态。

## 四、产物与路径

| 产物 | 路径 | 命名规则 |
|---|---|---|
| 客户卷复盘 | `research/<客户>/复盘-<YYYYMMDD>.md` | 事实/判断/行动/遗留 |
| 插件仓复盘 | `docs/retros/<YYYY-MM-DD>-<事件>.md` | 按 `docs/retros/README.md` 模板 |
| 坑卡草案 | `docs/retros/` 下附录或单独文件 | 脱敏，含触发条件与防范动作 |
| 方法更新建议 | 汇报正文 + 提案给 Lead | 不直接改已定稿方法；改前先备份 |

## 五、边界（不做什么）

- 不编造成果与因果；复盘不是汇报美化，失败与未完成要写。
- 不把客户真名、金额、人名、涉密信息写进插件仓方法库；案例必须脱敏。
- 不直接改 `reference/雷区清单.md` / `methods/` / `AGENTS.md` 等已发布规则——先出建议，由人审后合入。
- 不做「一文多用」：客户卷复盘与插件仓方法沉淀分开写，互相链接。
- 不把复盘当追责材料；行动项对事不对人。
- 不把复盘写成表扬稿；不省略失败与未完成的部分。

## 六、相关方法与旧技能

- `docs/retros/README.md`（复盘模板与 Harness 六类）、`reference/雷区清单.md`（坑卡库，更新入口）。
- `docs/research/handbook-extract.md` §5.6（retro 骨架）、§7（进化回路：复盘→规则→hook）。
- 旧技能方法库中的「质量自检」与「红线」章节是复盘对照清单；不独立触发。
