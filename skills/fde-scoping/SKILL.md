# fde-scoping · 场景选择与数据体检

> 定位：把客户的需求池收敛成**一个可启动场景**，给出可复核的「做 / 补证 / 不做」结论，并把范围边界与数据前提落到文件上。它是 `solution` 之前**可拒绝的关卡**，不是需求收集会。
> 铁律：四条硬门槛任一不过就不启动；每一维分数必须有依据；否决项例外只能由人签字；门禁只有人能过。

## 一、触发时机

- 「客户想做的很多，先做哪个」「这些场景都能做吗」「先做个 Demo 试试」。
- 客户进入 `scoping` 场景阶段，门禁缺场景评估、数据可得性清单或范围边界。
- 会面后拿到候选场景清单，要在写方案/报价前先判定可做性。
- 数据情况不清、验收口径不清、发起人只是礼节性挂名，需要先体检。
- 不触发：写正式方案/报价（`fde-solution` + `methods/07`）、会面材料（`fde-meeting`）、实施交付（`fde-delivery`）。

## 二、输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 会面记录 / 需求清单 | 是 | 每个候选场景的触发动作、角色、频率、现状耗时 |
| 客户数据与系统情况 | 是 | 数据在谁手里、能否给样本、接口是否开放 |
| 决策链与发起人信息 | 是 | 姓名、职务、谁签字、谁每周投入 |
| 客户预算与采购流程 | 建议 | 决定 90 天上线是否现实（审批/采购周期） |
| 采购/招标记录（可选） | 否 | `fde_bid` / `bid_search`：该单位近期在买什么（只作证据，不作需求） |
| 方法/模板 | 是 | `methods/06`、`templates/场景评估表.md` |

## 三、执行步骤（逐条可检查）

1. **收需求池**：每个候选场景落一张卡——触发动作 / 使用角色 / 输入 / 输出 / 频率 / 现状耗时 / 现状做法。检查：每张卡有「触发动作」与「频率」；场景数 ≤8，其余进「下批场景池」。
2. **过四条硬门槛**：逐条问客户并判定 `true/false`：有姓名发起人、14 天首次对接、90 天生产上线、使用可测。检查：每条有证据位置；不确定一律 `false`；任一 `false` → 结论「暂不启动（补前置条件）」，不进入评分。
3. **数据体检**：按 `methods/06` §6 的字段级清单，先要 50–200 条样本、再谈权限；给每个数据域标 R0–R3。检查：核心字段清单到字段级，`data` 维得分不超过就绪等级上限；R0 直接触发否决项 1。
4. **12 维打分**：与客户业务负责人同场打分（1–5）；逐维写依据（客户原话/样本/文档 URL/截图）。检查：无空依据维度；空依据按 3 分封顶；改分留痕。
5. **归一化与档位**：`Σ(得分×权重) ÷ 101`（权重合计 101，**不得除以 100**）；≥3.6 且门槛全过且无否决 → 进方案；3.2–3.6 → 补证/小 POC（≤2 周）；<3.2 → 拒绝或转咨询。检查：计算过程写在评估表里，可手算复核。
6. **否决/降级**：逐条判定 10 条否决项（映射 `vetoes 1–7`）与 5 条降级建议；命中即不进入方案。检查：命中项写明处理；例外有签字人/日期/理由；第 10 条商务判断不编码、如实记录。
7. **写范围与边界**：in-scope（≤3 条）、out-of-scope（≥3 条）、依赖、假设、客户责任、暂缓清单、验收口径初稿。检查：out-of-scope 不少于 3 条；每条依赖有责任人与时间。
8. **客户确认**：把「场景 + 范围 + 发起人 + 验收口径初稿」整理成一页，由人拿去确认；确认结果写回评估表。检查：未确认不写成已确认；不替客户拍板优先级。
9. **落盘与回报**：三份产物写 `scoping/` → `fde_item {action:'report', kind:'ready', text:≤300字, artifacts:[路径]}`；`scoping` 门禁的 6 个人工项**留给人**在面板确认。检查：未调用 move 推进阶段、未勾门禁。
10. **交 solution**：把范围边界、数据清单、粗成本带（人力/数据/合规/云量级）交给 `fde-solution`；报价按 `methods/07` + `fde_quote`，不在本阶段报价。检查：交接清单齐全，成本只是量级不是报价。

## 四、产物与路径

| 产物 | 路径 | 必含内容 |
|---|---|---|
| 场景评估 | `research/<客户>/scoping/场景评估.md` | 四条门槛 + 12 维评分 + 归一化分 + 否决项 + 结论 + 签字 |
| 数据可得性清单 | `research/<客户>/scoping/数据可得性清单.md` | 字段级清单 + 就绪等级 + 体检结论 + 补数据清单 |
| 范围与边界 | `research/<客户>/scoping/范围与边界.md` | in/out-of-scope + 依赖 + 假设 + 客户责任 + 暂缓 + 验收口径初稿 |
| 场景评估空白表 | `templates/场景评估表.md` | 复制填写，字段与 `fde_scenario` 一致 |
| 门禁状态 | `research/.fde/board.json` | 由 `fde_board` / 面板读写，**不手改** |

## 五、工具与方法

- **`fde_scenario`**：`action=evaluate` 传 `scenarios[]`（`gates` / `scores` / `vetoes` / `note`），返回排序、Markdown 与缺项；`action=template` 返回空白表。工具只算数，不替人做结论。
- **`fde_bid` / `bid_search`**：会面后补采购证据（对方在买什么、谁中标）；候选人 ≠ 中标人，金额只引原文。
- **`fde_library`**：查「场景评估 / 价值评估 / build vs buy」相关权威资料（按阶段筛 `scoping`）。
- **`fde_board`**：读阶段与门禁缺口；推进/过门禁只能由人在面板执行。
- **模板与配置**：`templates/场景评估表.md`、`methods/06-场景选择与数据体检.md`、`reference/fde-pricing.json`（仅 solution 报价用）。
- 宿主未重启、工具不可用时：按 `methods/06` 与模板手算，并在材料里注明「工具未生效，手工计算」；**不凭记忆编分数**。

## 六、边界（不做什么）

- 不替客户决定做哪个场景、不替客户排优先级——只给评分、排序与建议，由客户业务负责人确认。
- 不自行过门禁、不推进阶段、不标注「客户已确认」；确认以书面/邮件/会议纪要为准。
- 不报价、不承诺工期与效果；成本量级不是报价，正式报价走 `fde-solution` 与 `fde_quote`，由人复核。
- 不虚构数据可得性：拿不到样本就写「未取得」，C 级线索不得当数据就绪依据。
- 不跳过合规预判；涉密/等保/备案只写触发条件与待确认事项，不构成法律意见。
- 不把「Demo 演示」当场景；Demo 单独计价并写转正条件。
- 不改客户卷定稿、不删除历史材料；多场景评估分别建文件，不混写。
