# fde-meeting · 会面材料与会面后记录

> 定位：一次会面产出一套**分层**材料：Brief（现场用）→ 合作地图（谈什么）→ 研判底稿（支撑追问）。写法细节在 `meeting-prep`（方法库）与 `methods/03`，本技能负责按对象层级组织并落盘。
> 铁律：**对象分层**——一把手讲战略与资产，分管讲技术可行性与责任边界，执行层讲场景与工期；同一客户多场会面分别重做材料。

## 一、触发时机

- 「明天/后天要见某集团的某人」「准备会面材料」「第一拜访该聊什么」。
- 客户进入 `meeting` 阶段，门禁缺 Brief 文件或干系人。
- 会面后要补事实：谁说了什么、哪些是 A/B/C、下一步谁负责。
- 「上次会面记录找不到了」→ 会面记录归档客户卷，并补进 board 时间线。
- 会面前查「对方最近招过什么、谁中标」→ 用 `fde-bid-radar` 补采购证据，再写 Brief。
- 会面结束要交接待场景评估（`scoping`）→ 先整理需求池、发起人、数据情况三样，再启动 `fde-scoping`。
- 不触发：写正式方案（`fde-solution`）、做调研底稿（`fde-discovery`）、场景打分（`fde-scoping`）。

## 二、输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 客户 + 见面对象姓名/职务 | 是 | 职务未确认时用中性称呼（「贵单位领导」） |
| 见面性质 | 是 | 初次拜访 / 方案汇报 / 谈具体项目 / 回访 |
| 客户画像与 KPI 假设 | 是 | 来自 `fde-discovery` 的产物，没有就先补 |
| 会面目标 | 是 | 三个必达目标，写清「当场要拿到什么」 |
| 时间/地点/人数 | 否 | 决定材料篇幅与打印份数 |
| 客户近期招采记录 | 建议 | `fde_bid`/`bid_search`：对方作为采购单位/中标人的公告，写进 Brief 速查数据 |

## 三、执行步骤（逐条可检查）

1. **定对象层级**：top（一把手）/ vp（分管）/ exec（执行层）/ unknown。检查：材料侧重点与该层级对应表一致；unknown 用中性称呼。
2. **写 Brief（3–5 页，60 秒可读）**：八节固定——三句话记住这个人 / 核心判断（只讲哪两件事）/ ★KPI 假设前三条 / 开场逐字稿（60–90 秒）/ 三个入口 / 必问五题 / 硬边界三条 / 收尾（当场要拿到什么）。检查：八节齐全，开场引用对方**具体做成过的一件事**。
3. **写研判底稿（8–12 页）**：会面定位与目标 / 公开画像（履历与公开动作轨迹）/ 组织在本议题上的现状（已有能力，不得重复建议）/ 全量 KPI 假设 + 汇总表 / 合作入口 / 议程建议 / 风险与边界 / C 级待核实清单。检查：议程里「请教」时间占一半以上。公开画像补一段「近期招采动作」：招标项目、中标人、金额原文（不求和）——用 `fde-bid-radar`。
4. **写合作地图（4–6 页）**：按**客户业务方向**分组（不按我方产品分组），每组写「合作机会 / 具体内容 / 对接载体 / 可检查结果 / 卡点」。检查：每条机会都有可检查结果，没有「赋能/共建」这类不可验收表述。
5. **写边界纪律**：三类必写——不做对方已有的、不碰对方内部单位地盘（若客户有下属数智单位，单列关系设计与协作原则）、不做超责任承诺（不替代专业判断与签发）。检查：「不做什么」一节存在且 ≥3 条。
6. **称谓与数字核对**：国企/院所职务逐字核对；引用数字标 A/B/C；不确定的人名职务不进材料。检查：无未确认全名、无没来源的数字。
7. **格式**：默认只交 md，落 `meeting/`；PDF 仅在明确要求「打印带进场/发文件」时才导出到 `exports/`，导出后用 `rw_qa_pdf` 自检。检查：没有主动生成的 PDF。
8. **会后 24 小时内补记录**：把对方原话与承诺按 A/B/C 落盘；更新 board 干系人（`stakeholders`，含 `level` 与 `verified`）与 timeline；给下一步 item。检查：会面记录有日期、对象、级别；下一步有 owner 与到期。

9. **会后交接 scoping**：汇总「需求清单 + 发起人线索 + 数据/系统情况」，每个候选场景写成一张卡（触发动作/角色/频率/现状耗时）落 `scoping/需求池.md`，再启动 `fde-scoping`。检查：三样齐全；没有交接就不进入 `scoping` 阶段；不在此阶段承诺价格。

10. **会后交回复盘素材**：标出本次验证/推翻的 KPI 假设，交给 `fde-harvest` 做方法沉淀（脱敏）。检查：有「假设命中/未命中」记录。

## 四、产物与路径

| 产物 | 路径 | 命名规则 |
|---|---|---|
| 现场 Brief | `research/<客户>/meeting/面谈Brief-<对象>-<YYYYMMDD>.md` | 对象写在文件名里，多场不混用 |
| 研判底稿 | `research/<客户>/meeting/研判底稿-<对象>-<YYYYMMDD>.md` | 完整版，前一晚通读 |
| 合作地图 | `research/<客户>/meeting/合作地图.md` | 可随会面更新，保留版本注释 |
| 会面记录 | `research/<客户>/meeting/会面记录-<YYYYMMDD>.md` | 原话 + 分级 + 承诺 + 待核实 |
| 需求池（交 scoping） | `research/<客户>/scoping/需求池.md` | 每场景一张卡：触发动作/角色/输入/输出/频率/现状耗时 |
| 按需导出 | `research/<客户>/meeting/exports/` | 仅明确要求时生成 |

## 五、边界（不做什么）

- 不报价、不承诺资源与工期、不越级承诺；金额类只用公开区间并标口径。
- 不越层级：给执行层讲战略、给一把手讲技术细节都算材料错位。
- 未确认的姓名/职务不进材料，一律中性称呼；不替用户约见或对外发消息。
- 不把内部话术、竞争判断、私人判断写进会对外递交的材料。
- 不主动导出 PDF/DOCX；不手改导出件，改 md 后重出。
- 不把会面记录写成评价：只记录原话、事实与承诺，判断单列。
