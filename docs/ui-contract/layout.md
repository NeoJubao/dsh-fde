## 0. 适用范围

| 项 | 内容 |
|---|---|
| 宿主 | DeepSeek Harness 0.2.0-rc.2 · `main` keyed slot 的一个面板（不是整窗） |
| 客户端 | `src/ui/ui-panel.js`（纯 JS `h()`，无 JSX/tsc/CSS Modules） |
| 不适用 | 宿主自身的窗口 chrome、侧栏、右栏、设置页；本契约只管 FDE 面板内部 |
| 术语 | **区域（Region）**=面板内一块有稳定 id 的位置；**页型（Page type）**=一类页面的区域集合；**焦点槽（Focus slot）**=覆盖在页面上处理单个对象的层 |

**FDE 用 JS 注入 CSS，不受 CSS Modules 约束**：`ui-panel.js:86-654` 是一个作用域在 `.fde-root` 的 CSS 模板字符串。CSS Modules 是打包器约定，用不上不算违规；本项目需要替代它的是「单一作用域 + 单一入口 + 本契约」。目前 `.fde-root` 作用域已具备，缺的是本契约的其余部分。

## 1. 落位决策树（totality：必须走到唯一区域，或停下）

新需求进来时**按顺序**问，遇到第一个「是」就停：

```
Q0 它是不是「改某个已存在对象的状态/字段」？
   └ 是 → 焦点槽 F1（REGION.DRAWER）内的 block-*；
          需要跨对象比较或批量 → TOOLBAR（仅 workbench/ledger 页型），并走 §9 变更流程
Q1 它是不是「我现在该做什么」的聚合（需要人动作的事）？
   └ 是 → 页型 inbox 的 PRIMARY（分组呈现，见 §4）
Q2 它是不是「一组对象处在流程哪一步 / 怎么推进」？
   └ 是 → 页型 workbench 的 PRIMARY（看板或等价的空间布局）
Q3 它是不是「全量对象查找/筛选/批量」？
   └ 是 → 页型 ledger 的 PRIMARY（+TOOLBAR）
Q4 它是不是「方法、规则、资料、说明」这类只读内容？
   └ 是 → 页型 reference 的 PRIMARY；只与某对象相关的资料 → 焦点槽的对应 block-*
Q5 它是不是「阈值、开关、自主性、安装状态」这类配置？
   └ 是 → 页型 settings 的 PRIMARY（入口在 PAGE_HEADER，不占页签）
Q6 它是不是「一次性确认/驳回/证据」？
   └ 是 → 焦点槽 F2（REGION.DIALOG）
Q7 它是不是「跨页型的全局控件」（刷新、自主性徽章、设置入口）？
   └ 是 → **壳层唯一一处**：PAGE_HEADER，且每个控件全面板只出现一次
否则 → **停下，走 §9 变更流程**。
不得落到「最接近的区域」。这条是契约的核心：没有兜底，才有约束力。
```

**判定记录要求**：任何新增区域/新增页型/新增抽屉层的改动，必须在 PR/提交说明里写一行「落位记录」：
`需求 → Qx → REGION.y（页型 z）`。没有这一行，视为未过契约。

## 2. 区域白名单（每行含「禁止放什么」）

列说明：**允许放**=该区域的职责；**禁止放**=唯一能变成检查项的一列（写「不许」而不是「最好不」）；**页型**=允许出现的页型；**边界**=层级/滚动/焦点行为。

| 区域 id | 允许放什么 | 禁止放什么 | 页型 | 边界 |
|---|---|---|---|---|
| `root` | 主题变量作用域、页面骨架 | 任何具体业务内容；任何主题选择器（明暗只靠宿主 token） | 全部 | 唯一根；持有 `data-region` 锚点 |
| `page-header` | 页面名（1 个）+ 一句定位；页级主操作 ≤1；视图级切换；设置入口 | 全局控件副本（刷新/自主性只在壳层 1 处）；统计数字；对象级操作 | 全部 | 常驻不滚动；窗口 chrome 避让在本区域 |
| `nav` | 5–6 个页签 + 分组分隔 + **单一语义**计数 | 对象级操作；超过 6 个页签；两种语义的计数徽章（待办数 vs 记录数）；参考/配置页签 | 全部 | 常驻不滚动；≤6 项时不需要横滚 |
| `status` | 加载 / 空 / 错误 / 降级 / 陈旧数据提示；恢复动作 ≤2 | 用状态条替代页面结构（空态仍须渲染结构 + 主行动）；无原因的纯报错 | 全部 | 位于 header 与 content 之间；不遮 nav |
| `content` | `toolbar` / `primary` / `aside` / `inbox-grid` 的组合 | 第二个 toolbar；跨页型混装（台账里嵌看板） | 全部 | 唯一滚动容器（页级） |
| `inbox-grid` | 今日四个同级块：待我处理（action）/ 建议 / 今日焦点 / 最近活动；每块 = 标题条 + 块内滚动 body | 其他页型；跨页型混装；页级主操作；把待办搬到页头 | inbox | 四宫格：宽档 4 列 / 中档 2×2 / 窄档单列；宽档页面级不滚动，仅块内滚动 |
| `toolbar` | 视图模式切换、搜索、筛选、排序 | 刷新（属壳层）；对象级操作；全局设置 | workbench / ledger | 每页 ≤1；随内容滚动或 sticky 二选一 |
| `primary` | 当前页型的主对象（列表/看板/表单/文档正文） | 广告位；跨页型推荐；同一对象第二遍重复 | 全部 | 占据剩余高度；长列表自身滚动或整页滚动（页型内统一） |
| `aside` | 摘要、图例、推荐、活动流；可折叠 | 主对象的全量副本（如把看板客户再列一遍）；页级主操作 | inbox / workbench / reference | 每页 ≤1；窄宽度下折叠到 primary 下方 |
| `drawer` | 单个对象的切面；最多两层（对象 + 子对象），第二层必须可返回 | 全量列表 / 跨对象比较；同一时间 >1 个抽屉；替换式切换（丢上下文） | focus | 遮罩覆盖 content；ESC + 点遮罩关闭；焦点陷阱 |
| `drawer-head` | 对象名 + 阶段/状态 + 面包屑返回 + 关闭 | 主操作按钮（属 foot）；未标注的裸 id 串 | focus | 不随 body 滚动 |
| `drawer-body` | `block-*` 分块；块标题可 sticky | 全局控件；跨对象内容；无分块的超长表单 | focus | 唯一滚动容器（抽屉内） |
| `drawer-foot` | 1 个主操作 + ≤2 个次操作 + 危险操作（视觉分离） | 多个同等强调的主按钮；保存类按钮散落正文 | focus | 固定不滚动 |
| `dialog` | 一句话说明 + 原因/证据输入 + 取消/确认（危险操作双确认） | 表单编辑（应回抽屉）；关闭即丢输入的流程 | focus | 叠在 drawer 之上；同一时间 ≤1 个 |
| `block-overview` | 身份、阶段、优先级、负责人、到期 | 门禁/下一步（各有专块） | focus | 默认展开 |
| `block-gate` | 自动检查、人工确认、证据输入、重新评估 | 推进阶段按钮（属 foot）；绕过证据的默认勾选 | focus | 默认展开（当前目标阶段） |
| `block-next` | 做什么 / 到期 / 负责人 / 保存 | 会话发起（属 foot） | focus | 默认展开 |
| `block-stakeholders` | 姓名/职务/层级/是否核实 | 联系方式明文落盘 | focus | 默认折叠（按需展开） |
| `block-artifacts` | 该对象的文件清单 + 打开/导出 | 跨客户文件；批量导出主按钮 | focus | 默认折叠 |
| `block-bids` | 关联公告、匹配候选、关联/取消关联 | 把候选人写成中标人；无出处的金额 | focus | 默认折叠 |
| `block-timeline` | 事件 + 时间 + 来源（人/agent/系统） | 可编辑正文 | focus | 默认折叠，最近 N 条 |
| `block-items` | 该对象的任务摘要 + 打开 | 全量任务看板副本 | focus | 默认展开 |
| `block-report` | 回报文本 + 产物路径 + 回报类型 | 长文全文（应落文件给路径） | focus | 默认折叠 |

> 新增区域必须同时改：本表 + `region-ids.mjs`（`REGION_IDS`/`REGION_META`）+ §4 页型集合 + 附录 C 迁移清单，并跑 `audit-ui-contract.mjs` A1。

## 3. 外壳（Shell）

### 3.1 区域树（目标态）

```
root
├─ page-header
│   ├─ 页面名 + 一句定位（左）
│   ├─ 页级主操作（右，≤1；inbox 无主操作）
│   ├─ 设置入口（右，gear）
│   └─ 视图级切换（仅 workbench：阶段看板/任务看板；ledger：清单）
├─ nav（5 页签 + 分组：工作台│参考│台账）
├─ status（载/错/空/降级/陈旧；可空）
└─ content
    ├─ toolbar（仅 workbench/ledger）
    ├─ primary（workbench / ledger / reference / settings）
    ├─ aside（仅 workbench/reference，可折叠）
    └─ inbox-grid（仅 inbox；四宫格：待我处理 / 建议 / 今日焦点 / 最近活动）

focus（覆盖层，不参与布局）
├─ drawer ─ drawer-head / drawer-body / drawer-foot
└─ dialog
```

### 3.2 外壳规则

1. **全局控件唯一**：刷新、自主性徽章、设置入口、经典模式入口，每个全面板只出现 1 次，都在 `page-header`。页内不得再放（现状违规见 §10 R1）。
2. **状态不遮结构**：错误/空态在 `status` 或 `primary` 内渲染，`nav` 与 `page-header` 必须保持可用（现状看板空态把 8 列全删掉，见 §10 R5）。
3. **窗口 chrome 避让**：面板是 `main` 入口页，顶部必须让出宿主发布的 `--dsh-frame-top-clearance`（macOS 预留条），左上角必须让出 `--dsh-frame-leading-clearance`；内容不得落进窗口红绿灯/标题条。依据：`@deepseek-ai/dsh-client-ui-layout/README.md` §Window-chrome seat。现状 **未实现**（§10 R7）。
4. **用户字号**：正文基准跟随宿主 `--dsh-content-font-size`，不写死（现状写死 13px，§10 R8）。
5. **最小宽度**：面板在真实宿主可能被压到约 476–512px（官方布局：主区保 400px，右栏可占 45–70%，1440 窗口下右栏 45% = 面板约 512px）。本契约要求 ≥3 个可用宽度档，而不是只有 1100/720 两个断点。分档：宽（≥1200 内容宽）/ 中（900–1199）/ 窄（<900）。窄档：nav 收成下拉、toolbar 折行、aside 折叠到 primary 下方。

## 4. 页型（Page types）

| 页型 | 第一性问题 | 允许的区域 | 主操作（页级，≤1） | 现状对应 | 三态要求 |
|---|---|---|---|---|---|
| `inbox` | 现在该我做什么？ | page-header / nav / status / content / inbox-grid | 无（动作在每条待办内） | 今日 | 载/空/错 全要（页面级） |
| `workbench` | 这组对象处在什么状态、怎么推进？ | page-header / nav / toolbar / status / content / primary | 「新建客户」（当前缺失） | 看板（客户/任务） | 载/空/错 全要；空态仍渲染结构 |
| `ledger` | 全量对象在哪、怎么筛、怎么批量？ | page-header / nav / toolbar / status / content / primary | 视页而定（导入/导出/检索） | 客户清单 / 招采 / 工件 | 载/空/错 全要；筛选无结果 ≠ 无数据 |
| `reference` | 方法/资料/规则是什么？ | page-header / nav / status / content / primary / aside | 无（只读） | 流程 / 资料库 / 方法 | 载/空/错 全要；目录缺失要说明 |
| `settings` | 阈值/开关/自主性怎么设？ | page-header / nav / status / content / primary | 「保存」（失败要有可恢复提示） | 设置 | 载(初始)/错(读写)；空态不适用 |
| `focus` | 这个对象现在是什么、下一步做什么？ | drawer / drawer-head / drawer-body / drawer-foot / dialog | 1 个（推进/发起会话/保存三者择一，见 §5） | 客户抽屉 / 任务抽屉 | 块级载/空/错；不得整槽白屏 |

**页型不变式**

- 一个路由/页签只对应一个页型；一个页型可以有多个**视图模式**（如 workbench 的「阶段看板/任务看板」），但模式切换不得改变页型。
- 页型决定允许的区域集合；任何「本页临时多一块」都不允许，必须走 §9。
- 页级的「第一性问题」写进页面头的一句定位，不用营销语（如「客户经营 · 注意力 · 会话派发」这种三名词堆叠不算定位）。

## 5. 焦点位（Focus slots）

### 5.1 层级（最多两层）

```
L0 页面（不含对象详情）
└─ L1 drawer    客户 / 任务对象详情
   └─ L2 drawer 子对象（从 L1 打开的任务 / 关联对象）——必须能返回 L1
      └─ dialog 确认/强制/证据（可在任意层之上）
```

### 5.2 规则

1. **L1→L2 不替换**：现状 `openItem()` 直接 `setDrawer({type:'item'})`（`ui-panel.js:5096`），客户抽屉被替换且无返回路径 → 违反。L2 的 `drawer-head` 必须有面包屑「← 客户名」，关闭 L2 回到 L1。
2. **主操作唯一**：`drawer-foot` 只放 1 个主操作。客户对象的「推进阶段」是主操作（受门禁约束）；任务对象的「保存」与「回报」二选一为主，「保存」不应出现在 body 中部。现状客户抽屉正文同时有 `保存人工确认`/`保存下一步`/`推进到试点`/`启动会话` 四个黑色按钮 → 违反。
3. **危险操作分离**：归档/删除放 foot 最右，与主操作之间留分隔（视觉分隔由 design.md 定义）。
4. **焦点与键盘**：打开抽屉时焦点进入 `drawer-head` 的关闭按钮或标题；Tab 必须在槽内循环（焦点陷阱）；ESC 关闭；关闭后焦点回到触发元素。现状有 `autoFocus` + ESC，但**无焦点陷阱/inert**（§10 R6）。
5. **宽度**：抽屉宽由 design.md 的尺寸角色决定；在窄档（<900）抽屉占满内容区并成为「页面」，此时 `drawer-head` 必须有返回。
6. **不得在抽屉里做全量工作**：批量导入、检索全量、看板拖拽这类跨对象操作必须回页面（现状工件/招采详情块已接近该边界，保留只读摘要即可）。

## 7. 导航准入（Nav admission）

**准入规则（全部满足才允许成为页签）**

1. 有独立的**第一性问题**，且不能由已有页签回答；
2. 有自己的**主对象名词**（客户/任务/资料/文件/方法），不是另一个页签的筛选视图；
3. 是**任务模式**而不是参考/配置（参考类最多 1 个页签，配置类 0 个）；
4. 全面板页签 ≤6，按 3 组以内分组；
5. 计数徽章只允许**一种语义**，且必须能说出它是什么（现状：今日=待办数、客户=记录数，同排两种语义 → 违反）。

**目标导航（5 页签 + 页头设置入口）**

| 位置 | 页签 | 页型 | 覆盖的现状 | 理由 |
|---|---|---|---|---|
| 1 | 今日 | inbox | 今日 | 唯一回答「现在该做什么」 |
| 2 | 客户 | workbench + ledger | 看板（客户/任务）+ 客户清单 | 同一对象三种呈现（看板/任务/清单），一个页签内用视图切换表达，避免两套 schema |
| 3 | 资料 | reference / ledger | 资料库 + 招采 | 都是「外部信息输入」；子页签 资料库 / 招采（决策点 A：招采是否独立） |
| 4 | 流程 | reference | 流程 + 方法 | 方法论是产品卖点；方法正文按阶段上下文进入，不单列页签 |
| 5 | 文件 | ledger | 工件 | 产物台账，跨客户的导出/质检 |
| — | 设置 | settings | 设置 | 配置类不占页签，入口在 page-header |

**降级/删除项**

- 看板 → 合并进「客户」（workbench 的模式，不是页签）。
- 客户 → 保留，但作为「客户」页的清单模式（ledger）。

## 8. 非 happy path

| 状态 | 触发 | 必须给 | 禁止 |
|---|---|---|---|
| loading | 首次读取 / 慢网 | 骨架或 `Loading` + 正在读什么；>1s 才显示 | 空白页；把旧数据当新数据显示 |
| empty（无数据） | 集合为 0 | 一句为什么空 + 1 个主行动 + 1 个次行动/链接；**仍渲染页型结构**（看板空态渲染灰列） | 只给一句「还是空的」；空态里出现不存在的动作（现状：空态说「新建客户」但没有入口） |
| empty（筛选无结果） | 筛选后为 0 | 说明是筛选导致 + 「清除筛选」 | 与「无数据」共用文案 |
| error（页级） | 读取失败 | 发生了什么 + 原因 + 重试 + 检查安装/降级的指引；保留 nav | 只显示一行红字占满屏；保留旧计数且不标「陈旧」 |
| degraded（能力不可用） | bid-intel/资料库/MCP 未就绪 | `UNAVAILABLE` 说清缺什么、怎么恢复；页面其余部分照常 | 白屏；把不可用说成「没有数据」 |
| stale | 缓存非当日 | 「陈旧」标记 + 上次成功时间 | 静默使用旧数据 |
| partial | 部分字段/块失败 | 块级错误占位，不拖垮整页 | 整页报错 |
| permission/404 | 路由缺失 | 降级到经典模式或说明版本要求 | 伪装成功 |

现状对照：`today-error` 截图只给一行红条 + 空白页（无恢复指引、旧计数仍在）；看板空态删除 8 列（结构消失）；招采已有 `BidUnavailable`（正确，保留为范本）。

## 9. 变更流程（改这个契约本身）

1. **落位**：新需求按 §1 决策树走到唯一区域；走不到 → 停下，先讨论是否新增区域/页型。
2. **改文档**：改本文件（§2 表格行 / §4 页型 / §7 导航），与 `region-ids.mjs` 同步；**不许只改一处**。
3. **加标注**：渲染处用 `region(REGION_IDS.X)` 产 `data-region`，不手写字符串。
4. **跑体检**：`node audit-ui-contract.mjs` 必须 A1–A8 无 FAIL；再补：明/暗两套 + 宽/中/窄三档 + 空/错/载三态截图（人工项）。
5. **审查单位**：跨区域或跨页型的改动按官方「整页为审查单位」走一遍受影响关系（对齐/分组/层级/状态/几何），并记录「已检查无新增问题 / 已修复并复查 / 发现但未修复 / 未检查」。
6. **破坏性变更**：删除/重命名区域 id 必须先在 `region-ids.mjs` 标注 `deprecated` 并保留一个版本，再删。
