# Intent：调研工作台 → FDE 工作站

> 状态：已确认（Neo，2026-11-03）｜ 本文件是 spec 的第一节，spec 不改写本文件，只引用。

## 要做什么

把现有「调研工作台」插件重构为 **FDE 工作站**：一个围绕客户全生命周期（线索 → 研判 → 会面 → 方案 → 试点 → 交付 → 采用）的作战台。它同时是：

- **看板**：一屏看清所有客户现在卡在哪一阶段、下一步是什么、哪里缺证据；
- **待我处理**：只把真正需要人决定/审阅/回答/解阻的事推到最前面；
- **工单内核**：每个客户、每项任务都有状态、归属、门禁和报告，agent 可以在授权范围内自己推进并回报；
- **技能与方法的执行器**：把已沉淀的调研/核实/会面/方案/交付方法论变成可加载的 agent skill 和固定产物链。

## 为什么

现状是「一次性调研工具」：能立项、能抓取、能出材料，但 **项目之间是孤岛**，没有统一的状态、优先级、下一步、门禁和复盘；agent 每次都要重新组织工作，人无法一眼判断「今天该处理谁、卡在哪、还差什么」。

根本问题不是缺功能，是缺 **一个稳定的经营对象和一条稳定的推进流程**：客户经营的状态不在系统里，只在人的脑子里。FDE 工作站要把它外化成可检查的数据。

## 约束

- 运行在 DeepSeek Harness 0.2.0-rc.2，插件是**纯 JS、零构建依赖、link: 安装**；不能引入需要编译或需要新装 npm 包的运行时依赖。
- 现有 5 个工具（`rw_*`）、12 条路由、五页签面板、methods/scripts 必须继续可用；`research/` 下已有项目目录不能迁移、不能改目录结构。
- 宿主侧改动需要重启 DSH 才生效；客户侧面板可热更新。界面必须先兼容「宿主未重启」的状态，不能白屏。
- 单机、单用户（Neo）+ 少量协作者；不做多租户、不做账号体系。
- 默认 md 是唯一工作格式，PDF/DOCX 仅在明确要求时导出（沿用现有铁律）。
- 客户资料有保密差异：公开结论进客户卷，私人判断不进客户卷；导出/覆盖类操作必须先备份、后写入。

## 不做什么

- **不做 CRM**：不管销售漏斗金额预测、不管合同/回款/发票，不替代飞书/企微。
- **不做聊天客户端**：不接 IM 实时消息，不做群聊/通知中心（v1 只用面板和会话）。
- **不做多 agent 调度平台**：不复制 superagent 的 Source/Thread/Executor 全套；只借它的「工单 + 注意力 + 授权/自主性」内核，落在单机 DSH 上。
- **不做云端/多用户**：没有服务器部署，没有权限系统，没有 API 对外开放。
- **不自动替人做承诺**：agent 不得自行推进阶段门禁、不得自行对外发送材料、不得自行改客户卷中的定稿文件。
- **不引入第二套流程引擎**：FDE 看板是唯一编排者；`rw_*` 降级为执行工具，不再单独抢「帮我调研/写方案」这类意图。

## 成功指标

| 指标 | 定义 | 目标（上线后 30 天） |
|---|---|---|
| 看板覆盖率 | `research/` 下被识别为调研项目的目录中，进入看板的比例 | ≥ 90% |
| 注意力命中率 | 「待我处理」里真正需要人动作的条目占比（人工抽查） | ≥ 80% |
| 下一步缺失率 | 活跃客户中没有 `nextAction` 的比例 | ≤ 10% |
| 阶段停留时长 | 每个阶段的中位数停留天数 | 可观测即可；v1 只要求有数据 |
| 会话闭环率 | 从看板启动的 agent 会话中，用 `fde_item report` 回报结果的比例 | ≥ 70% |
| 单次操作耗时 | 新建客户 → 启动首次调研会话 | ≤ 3 次点击 / 60 秒 |

> 指标是产品验收的一部分：v1 先做到「有数据、可查看」，不要求达标；每个季度回看一次。

## 待定问题

1. 客户经营是否需要「商机金额/赢率」字段？（v1 只留 `value` 备注字段，不建预测模型）
2. 是否接入招标雷达（bid-intel）作为自动 Source？（v1 只留规则占位，默认关闭）
3. 多协作者时「归属人」如何工作？（v1 单人 + 自由文本 owner，不做成员体系）
4. 复盘产物放客户卷还是插件仓 `docs/retros/`？（v1：客户卷放事实复盘，插件仓放方法沉淀，两者互链）
