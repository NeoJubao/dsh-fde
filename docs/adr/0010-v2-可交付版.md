# ADR 0010：v2.0 可交付版（用词、提醒机制、客户抽屉与设置收敛）

- 状态：已接受（2026-11-19，Neo 指示「整体进行一次重构……为我决策……使产品达到可交付的标准状态」）
- 关联：`docs/01-spec.md` §1 / §5 / §6 / §8 / §22；ADR 0005（5 页签）、0006（示例数据）、0007（今日四宫格）、0008（资料页）
- 回滚：工作区 `.archive/dsh-fde-pre-v2-20261119-143501.tar.gz`；`board.json` 结构、路由、工具参数都没变，回滚不需要迁移数据。

## 背景

v1.7.0 功能齐全，但拿给第一次用的人看，问题集中在「看不懂」和「信不过」两件事上。以下都有截图或代码为证（重构前截图在本次会话的临时目录，结论已写入 `docs/02-plan.md` §11）：

1. **界面露出内部标识**。11 个文案 key 直接显示在界面上（`boardNoNext`、`customersStage`、`customersPriority`、`tabSettings`、`settingsAutonomy`、`libKindGuide` 等，v1.7.0 删经典模式文案时误删）；另有规则编号（`stall`、`due_soon`）、对象编号（`eng_a10005`）、检查项 key（`subject_locked`）、字段名（`company / source / nextAction`）、接口路径（`/fde/meta`）、状态文件名（`board.json`）。
2. **用词是系统的，不是用户的**。注意力、门禁、自主性、工件、泳道、回报、干系人、宿主——这些是数据模型的词，用户说的是「等我处理的事」「还差什么才能往下走」「让 AI 做」。
3. **说明文字在解释实现**。「全部从宿主 /fde/meta 读取」「规则引擎会在读取时生成」「设置写入 research/.fde/board.json（宿主会先备份）」，对使用者没有用。
4. **提醒不可信**。
   - 同一件事出现三次：一条逾期，既是「待我处理·逾期」，又是「待我处理·建议」，又在「建议」栏里。
   - 提醒不会过期：条件消失后仍挂着，标题里的天数也不更新；而待处理提醒上限 8 条，堆满后新提醒出不来。
   - 「采纳」多数是空操作：对「停滞」「即将到期」点采纳，只是把它标成已处理。
5. **设置里有没用的开关**。「目录监听」「打开即出简报」在宿主里没有任何读取点；「建议+一键执行」和「安全动作自动」两档的实现完全相同。
6. **客户抽屉要点很多次**。推进条件要先点「重新评估」才有结果；四个独立的保存按钮；每个确认项强制配一个证据输入框；主操作「启动会话」在抽屉最底部。
7. **看板要横向滚动才能看全 8 个阶段**，并用两行提示文字来解释怎么滚、怎么拖。

## 决策

### D1. 一张用词表：界面、提醒文本、记录文本、会话里对用户说的话，用同一套词

代码、数据文件、路由、工具参数里的英文 key **不改**（零迁移）。改的是所有给人看的中文。

| 内部概念（代码/数据） | 给人看的词 | 不再出现在界面 |
|---|---|---|
| engagement | 客户 | engagement、客户卷 |
| engagement.dir | 客户文件夹 | 客户卷、目录名 |
| item | 任务 | item、工单 |
| attention | 待我处理 | 注意力 |
| proposal | 提醒 | 建议、规则、ruleId |
| gate | 推进条件 | 门禁 |
| gate.auto | 材料（系统自动核对） | 自动检查（宿主计算，只读） |
| gate.manual | 需要你确认 | 人工确认 |
| force | 破例推进 | 强制通过、force |
| autonomy | AI 权限 | 自主性 |
| red lines | 只能由你决定的事 | 硬红线 |
| handoff | 交给 AI | 启动会话、会话派发 |
| report | 进展 | 回报 |
| lane | 状态 | 泳道 |
| stakeholders | 关键人 | 干系人 |
| artifacts | 资料 | 工件 |
| timeline / activity | 记录 / 最近动态 | 时间线 |
| stall | N 天没有进展 | 停滞 |
| stage stay | 本阶段第 N 天 | 停留、停 N 天 |
| WIP limit | 同时进行上限 | WIP |
| host | DSH | 宿主 |
| demo | 示例数据 | 演示模式 |

任务状态（lane）标签：`inbox` 待整理 / `todo` 待开始 / `doing` 进行中 / `waiting` 等对方 / `review` 待验收 / `done` 已完成 / `canceled` 已取消。

待我处理的分类（attention kind）标签：`blocked` 卡住了 / `decision` 等你决定 / `review` 待验收 / `answer` 等你回复 / `overdue` 已逾期 / `gate` 等你确认 / `stall` 没有进展 / `proposal` 提醒。

阶段名不变：线索 → 研判 → 会面 → 场景 → 方案 → 试点 → 交付 → 采用。「招采」「Brief」「A/B/C 证据分级」是这个行业和方法里的固定说法，保留。

### D2. 界面不出现内部标识

英文枚举、字段名、对象编号、检查项 key、文件匹配规则（「md ≥1」）、接口路径、状态文件名，一律不显示。

- 文案字典缺 key 时**构建失败**（`build.mjs` 校验：每个 `t('key')` 都必须在字典里），不再回退显示 key 名。
- 新增面板禁词检查（`verify/client-static.mjs`）：面板源码的中文文案里不得出现 D1「不再出现」一栏的词。

### D3. 说明文字只留三类

1. 后果提示：归档、删除、破例推进这类不可逆或要留痕的操作。
2. 空状态下的下一步。
3. 口径提示：招采的「候选人 ≠ 中标人；金额为公告原文」，每个页面只出现一次。

解释实现方式的小字全部删除。

### D4. 提醒机制：待我处理 = 必须有人动作；提醒 = 提前知会

- **不再生成与「待我处理」重复的提醒**。`stall`、`overdue`、`gate_ready`、`review_lag` 四条规则标记为 `derived: true`：它们的情形已由「待我处理」里的没有进展 / 已逾期 / 等你确认 / 待验收覆盖，并带有真实的处理动作。规则定义保留（`meta.rules` 仍是 8 条），只是不再产生提醒。
- **仍会产生提醒的四条**：`due_soon` 快到期、`no_next` 没定下一步、`meeting_soon` 会面快到了、`bid_signal` 客户有新招采公告。
- **提醒自动失效**：每次刷新时，条件已不成立的待处理提醒自动关闭（`status: 'dismissed'`，`expired: true`，不写动态记录）；条件仍成立的更新标题（天数保持准确）。`bid_signal` 是一次性事件，超过 `bidSignalDays × 2` 天未处理自动关闭。存量看板里四条 `derived` 规则留下的待处理提醒，在首次刷新时按同一机制关闭。
- **按钮说的是结果**：新招采公告 →「建跟进任务」；会面快到了 →「交给 AI 准备」；快到期 / 没定下一步 →「去处理」（打开客户或任务）；每条提醒都有「知道了」。不再有通用的「采纳 / 忽略」。
- **AI 权限两档**：「只提醒，由我决定」（`observe`，默认）与「小事可以直接处理」（`assisted`）。`auto` 与 `assisted` 实现相同，界面合并显示；数据里已是 `auto` 的保持原值。「小事」如实写明：给没定下一步的客户补一条待确认的下一步、为新招采公告建跟进任务。

### D5. 今日：保留一屏四块（ADR 0007），内容去重

四块为：**待我处理 / 提醒 / 今天跟进 / 最近动态**。

- 「待我处理」不再包含提醒；页签角标与顶部数字只算必须处理的事。
- 每行由结构化字段拼出标题，不带「受阻：」「待审阅：」这类前缀（分组头已经说明），客户名不重复出现。
- 每行最多一个主按钮加一个次按钮。
- 问候语下方显示日期，不再放解释性的一句话。

### D6. 客户：看板一屏看全，卡片说人话

- 子页签改名：**看板 / 列表 / 任务**。三个视图都有「新建客户」。
- 8 列随宽度均分，面板内容宽 ≥ 1180px 时不需要横向滚动；更窄时可横滚，不再用文字解释。
- 卡片：客户名、本阶段第 N 天、下一步（没有时显示「还没定下一步」）、到期（今天 / 明天 / 逾期 N 天 / 日期）、推进条件进度、招采条数。去掉文件数。空列不显示「（空）」。
- 删除拖拽与键盘操作的提示行（操作保留，写进 `docs/GETTING-STARTED.md`）。

### D7. 客户抽屉：按「接下来做什么」排

顺序：**下一步 → 推进到下一阶段 → 任务 → 关键人 → 资料 → 招采 → 记录**。

- 打开即核对推进条件，不再有「未评估」和「重新评估」按钮（保留一个刷新图标）。
- 材料与确认项合成一张清单；确认项的备注改为选填，点开才出现。
- 保存按钮只在有改动时出现。
- 主操作「交给 AI」放在推进条件下面：缺什么材料，就让 AI 去准备什么。
- 「破例推进」收进次级入口，必须写原因。
- 不显示对象编号；记录里不显示 `created · human` 这类字段。

### D8. 流程：指南而不是数据表

- 子页签改名：**阶段指南 / 方法库 / 技能与模板**。
- 删除「阶段 × 工具矩阵」（每个阶段自己的工具清单已经包含同样信息）。
- 点技能或工具，直接复制一句能粘贴到会话里的话。

### D9. 设置：五组，去掉没用的

- 分组：**AI 权限 / 提醒 / 数据来源 / 示例数据 / 运行状态**。
- 删除两个没有效果的开关（目录监听、打开即出简报）；`settings.sources` 里的字段保留，不迁移。
- 删除只读的「规则清单」。
- 改了就存，不再有「保存设置」按钮；已经有客户时不显示「示例数据」一组。
- 「健康检查」与「宿主重启提示」合并为「运行状态」。

### D10. 页头

去掉标语和 AI 权限徽章（它是设置项，不是需要常驻的状态）；刷新和设置是两个带文字提示的图标按钮。

### D11. 宿主返回给人看的文本一并改写

阶段指南（playbook）、推进条件的检查项名称、缺项原因、待我处理与提醒的标题、记录文本、健康检查项名称，全部按 D1 改写，不出现字段名和文件匹配规则。

存量看板里的旧记录不改写文件，面板显示时做轻量替换（只影响显示）。

### D12. 会话里的用词

系统提示词增加一条：对用户说话用 D1 的词，不说 engagement、item、gate、门禁、注意力。工具名与参数名是给模型用的，保持不变。

### D13. 版本

`2.0.0`。界面用词与信息结构整体变化，提醒的生成规则变化；数据结构、路由、工具参数不变。

### D14. 跟上 DSH 0.2.1（实施中追加）

实施期间用本机 DSH 0.2.1-rc.5 的官方包做了一次只读审计，实测出四个会直接影响使用的问题，一并在本版修复：

1. 技能注册对象缺 `source`，16 个技能能列出但加载必报错；
2. `scys_fde` 返回值带 `undefined`，每次调用都被判为非法输出；
3. 「在文件夹中显示」没传取消信号，原生通道一直失败；
4. 插件硬性依赖只有 Web 载体才有的两个服务，headless / acp / sdk 下不启动。

同时对齐了接口地址解析与几项样式约定。完整清单见 `docs/01-spec.md` §22.7。没有采用的新能力列在 `docs/02-plan.md` §11.6。

### D15. 实施中发现并修复的缺陷（追加）

这些不在最初的背景清单里，是改到相关代码、看到实际渲染后才发现的：

- 「新建任务」对话框无论负责人填不填都创建失败（面板提交自由文本，DSH 侧只接受三个固定值）。
- 打开客户抽屉不会核对推进条件（子组件的 effect 先于父组件，取不到客户 id）。单元测试里的简化渲染器掩盖了这个时序问题，是在离线渲染真实截图时发现的。
- 方法与模板里的否决项编号和 `fde_scenario` 的实现对不上。
- 客户全部暂停时问候语写「还没有客户」。
- 包里有一条写死的个人目录兜底路径。
- 已处理的提醒永久留在看板数据里。

### D16. 交给 AI 时，做法跟着要补的材料走（独立审查后追加）

推进条件属于**要进入的那个阶段**（`fde-schema.js`：阶段的 `gate` 是「进入该阶段前必须通过」的条件；spec §2.1 表头同义）。所以一个客户停在某一列，表示这一列的材料已经有了，手上在做的是下一列的材料。

1.x 到 2.0 初版在两处没有按这个口径走，本次改正：

- **交给 AI**：抽屉里列的是「进入下一阶段还差什么」，但发给 AI 的是当前阶段的做法（客户在「线索」，差的是事实核查清单，AI 拿到的却是线索登记的做法）。spec §9 原文就是「按目标阶段生成任务提示」，是实现偏了。改为：用**要进入的那个阶段**的做法与技能；没有下一阶段（已在「采用」）时用当前阶段。指定了目的的交接不受影响：准备会面用会面的做法，复盘用当前阶段。
- **看板卡片**：卡片上的「待确认 N」读的是当前阶段自己的条件，和抽屉不是同一组。改为和抽屉一致，读要进入的那个阶段；最后一个阶段不显示。
- **抽屉里的指南链接**：「这个阶段怎么做」打开的是当前阶段的指南。改为打开要进入的那个阶段，链接文字写明阶段名。

附带的三点：

- 自动建的任务标题改为「准备进入「<阶段>」：<客户名>」，类型用要进入的阶段；最后一个阶段仍是「推进「<阶段>」：<客户名>」。在办的旧标题任务照样复用，不重复建。
- 从已有文件夹导入的客户，是按「文件夹里有没有这个阶段的材料」放列的，当前阶段自己的材料可能不全（例如放在「方案」但没有成本测算）。这种情况下发给 AI 的话里加一行说明缺什么，并要求在进展里提醒人——补齐，或者把客户拖回上一列。AI 不自行补做，也不替人决定。
- 任务的交接按任务类型选技能（类型是阶段时）；否则按客户要进入的阶段。

数据结构、路由、工具参数都不变。

### D17. 方法库：移出「领域模型合作」，补上「试点、交付与采用」；方法文档脱敏（试用后追加）

- **移出**：`methods/04-领域模型合作方法论.md` 和技能 `domain-model-partnership`。它讲的是一类特定合作（多方共建领域模型、涉密场景的专项要求），不是每个 FDE 都会遇到的事，放在通用方法库里不合适。内容留在 git 历史里（`2d2346b` 及之前），需要时可以取回，不再随插件发布。
- **补上**：`methods/04-试点交付与采用.md`。方法库原来只讲到出方案，试点、交付、采用三个阶段只有技能、没有方法，也没有 Charter、验收清单、风险登记、价值证明的骨架。新方法讲 Charter 六项、指标四件套、部分达标怎么办、变更、价值证明五段、扩展地图，并附四份骨架。时间门限和判定规则都标「方法默认值（待验证）」。
- **接线**：方案阶段不再指向领域模型方法，改指向合作地图构建法（机会矩阵与边界纪律）；试点、交付、采用三个阶段的指南、交给 AI 的提示词、三个阶段技能都指向新方法。技能总数 16 → 15（11 个 `fde-*` + 3 个方法库 + 1 个通用），方法仍是 8 篇。
- **脱敏**：`methods/00`–`03`、`reference/雷区清单.md`、`reference/数据源清单.md` 等 10 个文件里，来自真实调研的日期、数字、地名、地方平台域名、行业称呼、可搜到的原话，换成不带行业的称呼和明显是举例的数字。规则、步骤、检查项、口径不变。系统提示词里指明招采数据来源平台的一句，改成「以本机招采雷达实际采集的为准」。

## 不做什么

- 不改 `board.json` 结构、不改路由、不改工具参数、不迁移数据。
- 不拆分 `src/ui/ui-panel.js`（单文件无构建依赖是 DSH 插件约束下的既定取舍；拆分列入 backlog，见 `docs/02-plan.md` §11.6）。
- 不改 5 个主页签的名称与顺序（ADR 0008 刚定）。
- 不新增依赖，不新增路由。
- 不改方法论的口径（四条硬门槛、12 维权重 101、定价默认值的「待验证」标注）。否决项编号的对齐是让文档与实现一致，不是改口径。
- 初版没有补写试点、交付、采用三个阶段的方法文档；试用后改了主意，已补上，见 D17。

## 后果

- 存量看板首次刷新后，「提醒」数量会明显减少（重复项与过期项被自动关闭）。这是预期行为。
- 设置里选过「安全动作自动」的用户，界面显示为「小事可以直接处理」，行为不变。
- 依赖旧界面文案的测试断言同步更新（`verify/client-static.mjs`、`fde-client.mjs`、`client-runtime.mjs`、`acceptance-audit.mjs`、`fde-host.mjs`），不删测试。
- `docs/ui-contract/` 的区域注册表随今日四块的命名更新；体检仍为 advisory。
