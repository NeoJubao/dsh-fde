# ADR 0009：移除经典模式（v1.7.0）

- 状态：已接受（2026-11-11，Neo 指示「经典模式的东西可以清理掉了」）
- 关联：`docs/01-spec.md` §8/§11、ADR 0005（5 页签 IA）、ADR 0008（资料页）
- 回滚：`git checkout -- src/ui/ui-panel.js && node build.mjs`；无数据迁移、无宿主路由改动。

## 背景

经典模式是 v1.0 遗留的旧五页签工作台（新建调研 / 项目 / 产物导出 / 素材 / 方法），在 v1.4 IA 收敛后仅作为「宿主未重启」时的降级入口保留（设置页与页头各有一个入口，另有一套 `.rw-*` 旧视觉 CSS 与 60+ 条只被它使用的文案 key）。v1.7 的 5 页签面板已稳定，双套 UI 带来维护成本与视觉噪音，用户明确要求清理。

## 决策

1. **删除客户端经典模式整块**：`ClassicApp`、`STAGES` 旧阶段常量、页头「经典模式」按钮、设置页「打开经典模式」入口、兼容页的「进入经典模式」按钮。
2. **宿主未就绪页保留但精简**：`/fde/meta` 探测失败时仍显示「宿主需要重启 DSH 后启用 FDE 看板」+ 探测原因 + 只读重启说明，**只提供「重试探测」**，不白屏。
3. **清理只被经典模式使用的资源**：`.fde-classic-*` / `.rw-*` CSS 整块、`DICT` 中 62 个失去引用的 key、`t('refresh')` 页内第二处（壳层唯一）。
4. **保留**：旧宿主 HTTP 路由（`/status`、`/projects`、`/scaffold`）与旧 `rw_*` 执行工具暂不动——它们不在界面出现，删除需要同步改宿主冒烟/安全/审计三套断言，风险与收益不匹配；后续可单独做宿主侧清理（列入 backlog）。
5. **版本**：随 v1.7.0 发布（未单发版本号）。

## 后果

- 客户端 `client.js` 从 420.9KB 降到约 386.8KB；界面少一套并行 UI 与两个入口，主题 token/字号统计基线随之变化（advisory A5/A8 数字更新）。
- 「宿主未重启」场景更简单：只有重试，不再有第二条降级路径；重启 DSH 是唯一恢复动作（设置页保留「重新探测 FDE 路由」）。
- 测试同步：`client-static` / `fde-client` / `acceptance-audit` / `client-runtime` 删除经典模式断言，改为「未就绪页只给重试」「经典模式已移除」；Finder 三通道降级测试保留。
- 已知限制：宿主 `/status`、`/projects`、`/scaffold` 三条旧路由成为面板不再调用的兼容保留路由（不在 FDE 路由僵尸检查范围内）。
