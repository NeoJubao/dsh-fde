# ADR 0006 · 首次上手：只读演示模式 + 一键清除

- 日期：2026-11-09
- 状态：已采纳（v1.5.0）
- 关联：`docs/01-spec.md` §3（settings）、§8（面板 IA）、`docs/GETTING-STARTED.md`、审查报告「首启死路」与空态问题
- 回滚：删除 `settings.demoDismissed` 即恢复默认（示例再次出现）

## 背景

新用户装完后看到的是空看板：虽然 Phase 0 已经有「新建客户 / 导入现有项目」空态，但第一次打开的人看不到「这个工具跑起来长什么样」，也不知道该先点什么。裸空态是流失点。

同时要避免两种错误做法：

1. **把示例客户写进真实看板**：示例会混入真实经营数据，客户名/阶段会误导人，清理还要删文件，风险高；
2. **纯 localStorage 记住「已看过」**：违反「状态落点唯一：只写 `research/.fde/`」的规则，换浏览器就重复出现。

## 决策

### D1. 演示数据是**只读客户端覆盖层**，不写盘

- 示例数据内置在客户端（`DEMO_BOARD` / `DEMO_BRIEF` 常量），**不写入 `board.json`、不创建 `research/<客户>/` 目录**。
- 展示条件：看板为空（`engagements.length===0 && items.length===0`）**且** `settings.demoDismissed !== true`。
- 演示期间所有写操作（拖拽、新建、注意力操作、启动会话、门禁勾选）**被拦截**，行内提示「示例模式不可操作；点「开始使用」后即可使用真实数据」。
- 演示内容明确标注「示例」：顶部常驻横幅 + 客户名带「（示例）」后缀；今日/客户页展示示例，其它页签显示真实（空）数据，横幅一直在，不做假数据。

### D2. 一键清除 = 持久化一个设置位

- 横幅按钮「开始使用（清除示例）」→ `POST /fde/settings { patch: { demoDismissed: true } }`。
- `settings.demoDismissed` 作为 board.settings 的普通布尔字段持久化（默认 `false`），随看板导出/备份，不新增状态文件。
- 清除后：看板回到真实空态（「新建客户 / 导入现有项目 / 重新查看示例」三步引导），示例**不再出现**。
- 设置页提供「重新查看示例数据」：写回 `demoDismissed: false`（仅在真实看板仍为空时显示示例；有真实数据时不显示，避免干扰）。

### D3. 与「空态引导」的分工

- **演示模式**回答「它能干什么」——给一个可看的成品；
- **空态引导**回答「我现在该点什么」——清除后给「新建客户 / 导入现有项目 / 重新查看示例」三步，其中「新建客户」是主操作。
- 两者不并存：有真实数据后既不显示示例，也不显示三步引导。

### D4. 不做什么

- 不做多步 tour / 引导遮罩 / 假数据交互演练（成本高、且容易被当真实数据）。
- 不把示例数据写进客户卷或 npm 包之外的任何状态。
- 不在有真实客户的工作区显示示例（避免误操作与数据混淆）。

## 后果

- 正面：首次打开不再空白；示例可看不可误写；清除后不复发；换浏览器/换机器也不会重复出现（设置在看板状态里）。
- 代价：示例内容需要随版本维护（字段与 schema 同步）；只读拦截要覆盖所有写入口，漏一处会写脏数据（用集中 `demoGuard` 包裹 + 断言兜底）。
- 未验证：真实宿主上的首启演示与清除链路（离线 harness 可验，重启后仍需人工看一眼）。
