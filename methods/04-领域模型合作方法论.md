# 领域模型合作方法论

> 适用场景：客户（大型企业/科研院所）要建"领域大模型/行业大模型"，已选定或需引入模型方（如智谱、百度、华为等），我方作为第三方参与推动。
> 建立于 2026-10-13（源自某研究院体系部项目）。

---

## 一、★ 第一原则：领域模型只是六层中的一层

**最常见的错误**：把"建领域模型"等同于"整个项目"。**实际上一个领域要真正落地，必须建六层**。

| 层 | 内容 | 典型主责方 |
|---|---|---|
| **① 模型层** | 基座选型、微调/蒸馏、训练算力、评测工具链 | **模型方**（智谱等） |
| **② Agent 层** | 系统级智能体、智能体自助创建/管理/优化、多智能体任务协作、模型-数据-业务系统衔接、**过程记录与结果验证** | **我方** |
| **③ 数据层** | 领域数据集、知识资产、**业务本体**（对象与关系显性化） | **我方 + 客户** |
| **④ 平台层** | 算力、平台、工具链、本地化/涉密部署环境 | **客户/集团**（常已有布局） |
| **⑤ 场景层** | "高价值、可闭环、可验证"的业务闭环 | **客户牵头 + 我方工程化** |
| **⑥ 机制层** | 组织（AI 建设岗）、责任矩阵、评估、培训、**能力移交** | **客户**（我方供方法） |

**用法**：谈合作时**先摊开六层**，再谈每一层谁主责。
- 只谈模型 → 我方无位置；
- 摊开六层 → 我方在 ②③⑤⑥ 四层有明确主责，价值立刻显现。

## 二、三方（或多方）角色设计法

### 2.1 第一步：弄清客户在"大盘子"里的真实角色

**雷区**：把客户当成"总包"。

**实例（某研究院）**：用户最初表述为"该院建十大领域模型"，实际是**集团规划十大领域模型，该院只承担其中一个领域**。

**正确问法**：
- 这件事是**集团/上级**层面规划，还是**本单位**自主？
- 本单位承担的**是其中哪一块**？
- 有无**依据文件**（规划、通知、专项）？

> **为什么重要**：角色判断错了，整套材料的层级、话术、交付物全错。

### 2.2 第二步：给每个合作方画"能力边界"

对每个合作方，填三栏：**核心资产 / 为什么需要它 / 最怕什么**。

| | 客户 | 模型方 | 我方 |
|---|---|---|---|
| 核心资产 | 领域知识与场景、专业人才 | 基座模型、训练推理工程、算力适配 | 业务本体方法、Agent 编排与治理、FDE 交付 |
| 为什么需要它 | 没有领域知识训不出模型 | 从零做模型代价过高 | 没有这层，模型训完**用不起来** |
| 最怕什么 | 训完模型没人用、数据出不去 | 场景不清晰、验收标准不明 | 被当成"又一个外包" |

### 2.3 第三步：写"谁都别做别人更擅长的事"

**必须显式写出边界纪律**（这是获得信任的关键）：

- ❌ 我方不做基座训练、不做算力供给 → 模型方
- ❌ 模型方不做领域知识结构化与业务本体 → 我方 + 客户
- ❌ 客户不从零搭平台/算力 → 承接上级/集团已有布局
- ❌ 我方不重复建设平台、不与模型方争模型层
- ❌ 任何一方都不替代人工决策与签发

## 三、涉密/军工场景的专项要点

> 军工、科研院所、涉密央企场景**必须**包含以下内容。

### 3.1 硬门槛

| 门槛 | 说明 |
|---|---|
| **保密资质** | 涉密环境开发常需**武器装备科研生产单位保密资格证书**；（实证：某研究院某项目 5 家投标、2 家因缺证被否决） |
| **数据不出域** | **训练数据能否出所/出域是全案决定性前提**，必须最先确认 |
| **环境隔离** | 离线/空气间隙部署、禁用外网、私有源（如私有 PyPI 镜像）、等保要求（如非 root 用户） |

### 3.2 合规问法（现场必问）

1. 训练数据是**全流程内网完成**，还是可**脱敏后出域**？
2. 参与各方（含外部合作方）的**资质门槛**是什么？
3. 模型与知识资产的**归属与移交**方式？

### 3.3 兜底方案

当外部方资质不足时，采用"**客户团队执行 + 外部提供方法与工具**"模式（我方供方法与工具，客户内部人员动手）。

## 四、把客户上级的战略语言变成我方话术

**做法**：抓客户**上级单位/集团**的公开会议原文，把其用词直接变成我方材料的骨架。

**实例（某航发集团）**——集团公开表述与我的回应：

| 集团原文（A 级） | 我方材料中的对应 |
|---|---|
| "**加电赋智、增数加算**"行动 | 开场引用，证明做过功课 |
| **四大短板**：能力建设碎片化、数据资源孤岛化、应用成效表层化、前沿跟进迟滞化 | 六层框架逐条对应解法（见下） |
| "**通用AI + 工程专业 + 组织闭环**"复合能力 | 六层中 ②Agent + ⑥机制 的定位依据 |
| "**高价值、可闭环、可验证**"的场景 | ⑤ 场景层的**准入标准与验收口径** |
| "**行业共享的高质量数据集**" | ③ 数据层的目标表述 |
| "**算力、平台和工具**等关键基础设施" | ④ 平台层（明确我方不重复建设） |
| "**明确各类主体责任**" | 直接支撑"一页纸责任矩阵"这个交付物 |
| **三年滚动计划** + "AI4E2""AI4S"先锋项目 | 三阶段节奏的对齐依据 |
| "每位学员提交**本单位本领域 AI 应用速赢速效项目初步规划**" | ★ 判断客户手上**有硬任务**，材料据此定位 |

**四大短板 → 解法映射表**（可直接复用）：

| 短板 | 解法所在层 |
|---|---|
| 能力建设碎片化 | ⑥ 机制层：统一范式与责任矩阵；先样板再复制 |
| 数据资源孤岛化 | ③ 数据层：业务本体让数据可关联、可追溯、可推演 |
| 应用成效表层化 | ⑤ 场景层：准入标准前置、验收指标前置 |
| 前沿跟进迟滞化 | ① 模型层：与前沿方建立持续合作机制 |

## 五、必备交付物清单

| 交付物 | 作用 | 关键要求 |
|---|---|---|
| **① 六层分工建议（一页纸）** | 现场可直接给的责任矩阵 | 横轴=合作方，纵轴=六层；必须含"都不做什么" |
| **② 会谈底稿** | 前一晚通读 | 含主体研判、上位战略、KPI 假设、风险、待核实 |
| **③ 现场 Brief** | 现场用 | 开场逐字稿 + 必问问题 + 硬边界 + 速查数据 |
| **④ 实施方案** | 会后递交 | 三阶段（速赢/样板/复制）+ 每阶段交付物 |

## 六、常见雷区

| # | 雷区 | 后果 | 防法 |
|---|---|---|---|
| **L1** | **把客户当成大总包** | 材料层级全错 | 先问"上级规划还是自主、你承担哪块、有无依据文件" |
| **L2** | **只谈模型层** | 我方无位置，只能当分包 | **先摊开六层**再谈分工 |
| **L3** | **假设训练数据可自由使用** | 方案根本不可行 | **最先确认数据出域边界** |
| **L4** | **忽略保密资质** | 人到现场进不去 | 入场前核实各方资质；准备"客户执行+外部供方法"兜底 |
| **L5** | **同名不同主体** | 谈错合作方 | 核实全称（实例：**智谱华章** vs **中航智谱**，分属不同央企体系） |
| **L6** | **不引用客户上级语言** | 显得不懂客户 | 抓集团/上级公开会议原文，用其用词做骨架 |
| **L7** | **一次想推十个领域** | 资源分散、全部不成 | **先做 1 个领域样板，形成范式再横向复制** |
| **L8** | **只讲模型指标不讲业务闭环** | 训完没人用 | 场景准入与验收指标**前置**到方案第一页 |
| **L9** | **忽视客户手上有硬任务** | 错过最大公约数 | 从上级要求里找客户的**硬任务与时间表**（如"速赢速效项目规划"） |

## 七、快速启动模板（接到同类任务时按此顺序做）

1. **立项**（`rw_scaffold`）
2. **锁主体与角色**：客户本单位 + 其上级单位 + 各合作方全称与角色
3. **抓上位战略**：客户**上级单位/集团**的公开会议原文（这是最高价值情报）
4. **抓合作方画像**：技术能力、**涉密适配能力**、央企案例、经营状况
5. **填六层表**：每层主责方与交付物
6. **写一页纸分工**：含"都不做什么"与前置条件
7. **写底稿**：含 KPI 假设（标注置信度）与待核实事项
8. **写 Brief**：开场逐字稿 + 必问问题 + 硬边界 + 速查数据
9. **写实施方案**：三阶段 + 每阶段交付物
