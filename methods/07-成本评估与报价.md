# 07 · 成本评估与报价（solution 方法）

> 用途：把「已确认的场景与范围」折算成**可复算的成本、可解释的报价和可执行的合同条款**，避免方案写完才发现报不起。
> 输入：`scoping/范围与边界.md`、`scoping/数据可得性清单.md`、客户预算与采购流程、模型/token 官方定价页（报价前现查）。
> 输出：`proposal/成本测算表.md`、`proposal/报价单.md`、`proposal/风险登记.md`（报价单可含 SOW 章节）。
> 工具：`fde_quote`（calculate / template）+ `reference/fde-pricing.json` + `templates/成本测算与报价单.md`。
> 铁律：**所有费率、毛利率、甜点区、合规费用都是「方法默认值 / 经验区间，待验证」，不是行业标准**；工具输出不构成对外报价，对外报价必须由人复核确认。

---

## 一、什么时候用

- 客户进入 `solution` 阶段，门禁缺 `cost`（成本测算）或 `quote`（报价单/SOW）。
- 客户问「这个大概多少钱」「预算够不够」「为什么这么贵」。
- 要出正式方案/投标/立项材料，需要可勾稽的成本与报价。
- 范围变更、折扣谈判、效果付费对赌前，需要重算底线与毛利。
- 不触发：场景选择（`scoping` / `methods/06`）、会面材料（`fde-meeting`）。

**报价在流程中的位置**：报价不是独立阶段，而是 `solution` 门禁的**必需子项**——`成本测算表 → 报价单 v1 → 客户预算/范围确认` 三件齐了，方案才算可过门禁。

## 二、成本结构：10 类成本项

|---|---|---|---|---|---|---|

| 6 | 差旅驻场 | 人天 × 日补 + 交通住宿实报 | 否 | 实报实销 | `nonLabor.travel` | C（经验区间，待验证） |

## 三、四种估算法（用哪个、怎么用）

| 方法 | 适用 | 做法 | 出处/级别 |
|---|---|---|---|
| 自下而上 | 范围清楚、WBS 可拆 | 拆任务 → 每任务人天 → 汇总 + 预备费 | 通行项目管理实践（B） |
| 类比估算 | 有同类历史项目 | 按相似度调整上项目人天（如 ×0.8 / ×1.2） | 通行实践（B） |
| 参数估算 | 有可量化驱动因子 | 人天 = a × 场景数 + b × 接口数 + c × 数据源数（系数需自有历史数据标定，**暂无公开权威系数**） | 通行实践（B） |
| **三点估算（PERT）** | 不确定性高（AI 项目常见） | `te = (o + 4m + p) / 6`；`σ ≈ (p − o) / 6`；报价用 P80 | PERT 定义（B） |

### 3.1 PERT 与 P80 口径（`fde_quote` 已实现）

```
te   = (o + 4m + p) / 6                    # P50 基准（期望值）
σ    = (p − o) / 6
P80  = te + 0.84 × σ                       # 报价计价人天：向上取 0.1 人天
```

- **计价按 P80**、**内部成本基线按 P50**：报价用 P80 对冲不确定性，成本管理用 P50 看偏差。
- 示例（方法示例）：工程师岗乐观 8 人天、最可能 10 人天、悲观 14 人天 → `te=(8+4×10+14)/6=10.33`；`σ=(14−8)/6=1`；`P80=10.33+0.84=11.17 → 11.2 人天`。
- 输入方式：`fde_quote.labor[]` 每行给 `personDays`（直接）**或** `optimistic/likely/pessimistic`（三点）；两种不能同时缺。
- 三点估算不是精确预测；σ 大说明信息不足，应先补数据/接口信息再报价。

## 四、三锚定价

| 锚 | 算法 | 用途 | 级别 |
|---|---|---|---|
| **成本加成（底线）** | 报价 = 成本 ÷ (1 − 毛利率)，或 成本 × (1 + 加成率)；含税 = 不含税 × (1 + 税率) | 保证不亏，给出报价下限 | 定义（B）；毛利率为经验值（C） |
| **价值定价（上限）** | 报价 ≤ 客户年化收益 × 分成比例（如 1/5–1/3，**经验区间待验证**） | 高 ROI 场景的谈判上锚 | 定义（B）；分成比例（C） |
| **竞品锚定（校准）** | 对比大厂 SaaS 年费、同类定制项目公开报价、公开采购记录 | 防止报高丢单/报低被疑 | 公开比价（B）；须逐条留来源 |

**使用顺序**：① 先用成本加成算出底线与目标价；② 有可靠年化收益口径时，用价值定价校验是否报低了；③ 用竞品锚定校准市场感知；④ 三个锚都写进报价底稿，最终价由人拍板。

> 本方法**不提供任何行业价目表**：公开可查的是产品定价页（A），交付报价没有公开权威数据（见研究底稿缺口）。没有竞品证据时，如实写「未取得公开可比报价」，不编造。

## 五、四种合同形态与推荐

| 形态 | 何时用 | 风险归属 | 对单兵/小团队的建议 | 级别 |
|---|---|---|---|---|
| 固定总价（Fixed Price） | 范围清楚、验收客观 | 供方承担范围与工期风险 | 报价必须含预备费；范围写死 + 变更单 | B |
| 工时材料（T&M） | 范围不清、探索性 | 需方承担超支风险 | 必须配「按量封顶」（guaranteed maximum price） | B |
| **里程碑付款** | 多阶段交付（FDE 主场景） | 双方共担 | **推荐默认**：按阶段验收付款（试点/交付/采用分段） | B |
| 效果付费/对赌 | 指标可测、可归因、有基线 | 供方承担效果风险 | **单兵不接全额效果付费**；可做「70% 固定 + 30% 与指标挂钩」，且写基线、归因与上限 | B / C |

**推荐组合：里程碑付款 + 按量封顶 + 变更单。** 付款节奏示例（方法示例，经验）：30% 启动 / 40% 试点验收 / 20% 交付验收 / 10% 质保金（3–6 个月后付）。现金流紧张时可把启动款提到 40–50%，但客户会要求更强的交付确定性。

**按量封顶规则（写进报价单）**：`预估量 + 单价 + 年度封顶 + 超量单价`；达封顶 80% 预警、100% 停止或转下一档。token/调用量、云资源、驻场人天都要有封顶或实报口径。

## 六、毛利率区间（**经验区间，待验证**）

> 以下不是行业统计，是本方法建议的内部测算区间；**禁止对外称「行业标准」**。

| 业务形态 | 毛利率建议区间 | 说明 |
|---|---|---|
| 定制交付（人力为主，单兵/小团队） | **35%–50%** | 低于 30% 时一个变更就亏；高于 50% 在国企/军工采购中常被质疑 |
| 产品化/可复制场景（第二客户起） | 50%–70% | 复用带来毛利提升，但要把「产品维护」成本算进去 |
| 纯人力外包/驻场 | 15%–25% | 不建议作为主业 |
| 试点（低价/免费） | 0% 或负 | 视为获客成本（Palantir S-1：试点常免费/低价），**但必须写「转正式的条件」** |

**报价速算（方法示例）**：成本 21.5 万、目标毛利 40% → 不含税报价 ≈ 35.9 万；若客户预算只有 30 万，则要么降范围（砍场景/砍集成），要么降毛利到 ≈28%（需人拍板，且预备费不能砍）。

## 九、变更单机制（防「白干」）

- **触发条件（任一）**：范围增删、验收口径变化、数据/接口不可用需替代方案、工期因客户原因顺延、合规要求变化、模型/第三方价格重大变化。
- **变更单字段**：编号 / 日期 / 变更内容 / 原因 / 对人天与费用的影响 / 对工期的影响 / 双方签字 / 关联报价版本。
- **规则**：**无签字变更单不施工**；口头变更 24 小时内补单；变更累计超过合同额 15% 时触发「重新报价/重新评审」（经验阈值，待验证）。
- **按量封顶**：token/调用量写「预估量 + 单价 + 年度封顶 + 超量单价」；达 80% 预警、100% 停止或转下一档。

## 十一、完整算例（**方法示例，不对应任何真实客户**）

### 11.1 输入

项目设定（虚构）：某国企「制度问答 + 合同条款审查」双场景，试点 + 首年运营，10 周交付，团队 3 人。

| 人力行 | 口径 | 人天/单价 | 小计（元） |
|---|---|---|---|
| 项目管理 | 直接人天 | 6 × 1,100 | 6,600 |
| FDE/算法 | 直接人天 | 18 × 1,200 | 21,600 |
| 工程师 | **三点估算** o=8 / m=10 / p=14 | P80 = 11.2 × 940 | 10,528 |
| 数据与评测 | 直接人天 | 8 × 800 | 6,400 |
| **人力合计** | P50 = 42.3 人天；P80 = 43.2 人天 | — | **45,128** |

| 非人力项 | 金额（元） | 依据/口径 |
|---|---:|---|
| 数据清洗/标注 + 评测集 | 7,000 | 经验区间（C） |
| 云与 token（首年） | 5,000 | 官方定价页现价 × 用量推算（A/C） |
| 合规（备案/评估支持） | 5,000 | **经验区间，待验证（C）** |
| 运维（首年） | 8,000 | 经验区间（C） |
| 差旅驻场 | 3,000 | 经验区间（C） |
| 质保（3 个月） | 2,000 | 经验区间（C） |
| 渠道/居间 | 0 | 本算例无 |
| **非人力合计** | **30,000** | — |

### 11.2 计算（与 `fde_quote` 公式一致）

```
直接成本   = 45,128 + 30,000 = 75,128
预备费 15% = 75,128 × 15%    = 11,269.20
成本合计   = 75,128 + 11,269.20 = 86,397.20
不含税目标价 = 86,397.20 ÷ (1 − 35%) = 132,918.77
含税目标价   = 132,918.77 × (1 + 6%)  = 140,893.90
成交价（无折扣）= 140,893.90；实现毛利率 = 35.00%
成本底线（0 毛利）= 86,397.20 × 1.06 = 91,581.03
报价上限（毛利 45%）= 86,397.20 ÷ 0.55 × 1.06 = 166,510.97
```

**校验**：直接成本 75,128 + 预备费 11,269.20 = 86,397.20 ✓；含税价 140,893.90 ÷ 1.06 = 132,918.77 ✓；`(132,918.77 − 86,397.20) ÷ 132,918.77 = 35.00%` ✓。

### 11.3 报价摘要与付款

| 项 | 金额（元） |
|---|---:|
| 成本合计（含预备费） | 86,397.20 |
| 报价（不含税） | 132,918.77 |
| 增值税（示例 6%，待财务确认） | 7,975.13 |
| **报价（含税）** | **140,893.90** |
| 30% 启动 | 42,268.17 |
| 40% 试点验收 | 56,357.56 |
| 20% 交付验收 | 28,178.78 |
| 10% 质保金 | 14,089.39 |

**工具警告检查**：报价 140,893.90 在甜点区 5–20 万内；云/运维/合规/数据项均非 0；预备费 15% ≥10%；P80 总人天 43.2 ÷ (10 周×5) = 0.864 人 ≤ 团队 3 人×1.2；非人力占比 30,000 ÷ 75,128 = 39.9% ≤40%——**无警告**（这是「干净」示例；下表情形会触发）。

### 11.4 敏感性（同算例，方法示例）

| 情形 | 计算 | 结果 | 判断 |
|---|---|---|---|
| 客户要求 10% 折扣 | final = 140,893.90 × 0.9 = 126,804.51；不含税 119,626.90 | 实现毛利率 **27.78%** | 低于经验区间 35%–50%，未触发 <20% 硬警告；需人确认或砍范围 |
| 客户要求 20% 折扣 | final = 112,715.12；不含税 106,335.00 | 实现毛利率 **18.75%** | **<20% → 工具告警「毛利过薄」**；正常应拒绝或砍范围 |
| 合规漏列 5,000 | 直接成本 +5,000、预备费 +750 → 实际成本 92,147.20；报价不变 | 实现毛利率 **30.67%** | 少 4.3 个百分点；合规项必须单列 |
| token 用量翻倍 | 云 token 5,000 → 10,000；实际成本 92,147.20；报价不变 | 实现毛利率 **30.67%** | 按量项必须有年度封顶 |

### 11.5 按量封顶与变更条款（写进报价单）

- token 年预算 5,000 元，**封顶 8,000 元**；超出按实际单价 ×1.2 结算；达 80% 预警；
- 变更单触发后按「新增人天 × 综合单价」计费；累计变更 >15% 合同额时重新评审；
- 报价有效期 45 天；合规审批等待期不计入交付工期；
- 付款：30/40/20/10（见 11.3），质保金 3 个月后支付。

> 整个算例只演示公式与勾稽关系；**所有单价、比例、合规费用均为方法示例/经验区间**，不得作为对外报价依据。模型 token 单价随版本变动，**报价前必须重抓官方定价页**。

## 十二、与 `fde_quote` 工具字段一一对应

### 12.1 输入字段

| 成本/报价要素 | `fde_quote` 参数 | 说明 |
|---|---|---|
| 人力行 | `labor[]` | 每行 `{name, personDays}` 或 `{name, optimistic, likely, pessimistic}`，可带 `rate` 覆盖默认费率 |
| 默认费率 | `defaultRate` | 缺省取 `reference/fde-pricing.json` 的 `defaults.ratePerPersonDay` |
| 数据与评测 | `nonLabor.dataEval` | 清洗/标注 + 评测集（AI 项目必填，0 会告警） |
| 云与推理 | `nonLabor.cloudToken` | token + 存储 + 向量库；0 会告警 |
| 合规 | `nonLabor.compliance` | 备案/评估/测评；0 会告警 |
| 运维 | `nonLabor.ops` | 首年运维；0 会告警 |
| 差旅驻场 | `nonLabor.travel` | 实报或包干 |
| 质保/售后 | `nonLabor.quality` | 质保期成本 |
| 渠道/居间 | `nonLabor.other` | 工具不单列渠道项；需保密时走线下，不写明细 |
| 风险预备费 | `contingencyPct` | 默认 15%（方法默认值） |
| 税率 | `taxPct` | 默认 6%（示例，以财务为准） |
| 毛利率 | `marginPct` | 默认 35%（经验区间下限） |
| 折扣 | `discountPct` | 成交折扣 |
| 团队规模/周期 | `teamSize` / `weeks` | 用于「人天与周期不匹配」告警 |
| 项目标识 | `engagementId` / `title` | 写入 Markdown 抬头；不写真实客户名除非显式传入 |

### 12.2 输出与警告

| 输出/警告 | 含义 |
|---|---|
| `summary.laborCost / nonLaborTotal / directCost / contingency / totalCost` | 成本链条，逐项可勾稽 |
| `summary.floor / target / ceiling / final` | 底线（0 毛利含税）/ 目标（默认毛利含税）/ 上限（毛利 +10pt）/ 成交价（含折扣） |
| `summary.realizedMarginPct / marginAmount` | 实现毛利率与毛利额（按含税价折回不含税计算） |
| `summary.p50PersonDays / p80PersonDays` | 三点估算下的人天基线 |
| `warnings[]` | 亏损 / 毛利 <20% / 超甜点区 / 云·运维·合规漏项 / 数据评测漏项 / 预备费 <10% / 人天与周期不匹配 / 非人力占比 >40% |
| `markdown` | 成本测算表 + 报价摘要 + 免责声明，可直接落盘再补客户信息 |

### 12.3 与 10 类成本的口径差异（必须知道）

- **税**在 `fde_quote` 中按**价外税**处理（`target = 不含税 × (1+税率)`），不进入 `totalCost`；若财务要求成本口径含税，用同一税率手工折算，**不重复计**。
- **风险预备费**是 `totalCost` 的一部分（按直接成本比例），不是报价外的加项。
- **渠道/居间**无独立字段，走 `nonLabor.other`；敏感信息不写进会进客户卷的明细。
- **质保**走 `nonLabor.quality`；**运维**走 `nonLabor.ops`，两者分开列，避免「免费无限修」。

## 十三、报价前自检清单

- [ ] 成本表每行有口径、数量、单价、小计、依据、封顶/实报；分项求和已校验。
- [ ] 数据评测、云 token、合规、运维、质保五项没有漏列（0 值有理由）。
- [ ] 三点估算的 o/m/p 有来源；P80 计价、P50 基线已注明。
- [ ] 报价单含 out-of-scope、假设与客户责任、除外条款、变更机制、验收质保、有效期六项。
- [ ] 金额口径分离：估算 / 控制价 / 成交价不混写；含税/不含税写明。
- [ ] 毛利率不低于 20%；低于 35% 需人确认；预备费未因砍价被砍。
- [ ] token/云/驻场等按量项有年度封顶与超量单价。
- [ ] 报价有效期覆盖合规等待期（30–60 天）。
- [ ] 模型/token 单价已按官方定价页现查（不抄旧数、不用记忆值）。
- [ ] 客户名、金额、人名等敏感信息未写进会进插件仓/对外的方法示例。
- [ ] 所有费率/毛利/合规费用已标「方法默认值/经验区间，待验证」；无「行业标准」表述。
- [ ] `fde_quote` 返回的 warnings 已逐条处理或写明接受理由。
