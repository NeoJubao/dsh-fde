# 05 · 正式对外文档交付（DOCX · 公文版式）

> 适用：材料**要正式发给客户**（递交、邮件附件、打印带进场、投标/立项），不是内部传阅、不是群里看一眼。
> 载体：md ＋ **可选**的 DOCX 生成器（需兼容 `scripts/build_docx.py` 契约，由使用者自备）；没装生成器就只交 md，不阻塞交付。
> 一句话：**md 是事实来源，DOCX 是对外载体。** 定版在 `对外材料/<客户卷>/`，正式件出在该卷 `exports/`。

---

## 一、先分清三种格式各干什么

| 格式 | 定位 | 什么时候用 |
|---|---|---|
| **md** | **唯一事实来源**，一切修改都在这里 | 内部工作、版本迭代、追溯 |
| **DOCX** | **正式对外载体**（可编辑、可批注、符合中文公文观感） | 要递交/发送给客户时 |
| **PDF** | 只读快照（防改、便于手机预览） | 用户明确说"打印/发文件/导 PDF"时，用 `rw_export_pdf` |

**不要主动生成 DOCX 或 PDF。** 只有"这份要正式发给对方"时才出 DOCX；用户没提就只交 md。

---

## 二、标准动作（六步）

1. **定版**：确认这份是不是最终对外版（依据见 `对外材料/00-定版规则与维护说明.md`），不是就先回去定版，别急着排版。
2. **放进对外卷**：md 复制到 `对外材料/NN-<客户>/`，文件名按 `<客户简称>-<材料类型>-<版本或日期>.md`，并在该卷 `00-本卷导读.md` 登记源路径与哈希。
3. **准备生成器（可选）**：DOCX 生成不是本插件内置能力。若本机已装一个兼容 `build_docx.py` 契约的生成器（例如自装的 `cn-procurement-docs` 技能），按它的说明加载；要改写正文就同时加载 `human-writing`（同样是可选依赖）。两者都没装 → 跳过第 4 步，只交 md，不影响交付。
4. **一条命令出 DOCX（可选）**（桥接脚本把 md → 内容块 → DOCX）：
   ```bash
   python3 research-workbench-plugin/scripts/md2docx.py \
     "对外材料/NN-<客户>/<文件>.md" \
     "对外材料/NN-<客户>/exports/<文件>.docx" --fonts gb \
     --skill-dir <含 scripts/build_docx.py 的目录>
   ```
   - `--skill-dir` 可省略：省略时脚本在常见技能目录里自动探测 `scripts/build_docx.py`；
   - `--fonts gb`：公文常用字体（仿宋/黑体/楷体/方正小标宋/宋体），给中文 Windows 收文方看 → **默认**；
   - `--fonts mac`：改用本机实有的 宋体/黑体，本地预览不走替代字体；
   - 已存在同名 DOCX 时加 `--overwrite` 才重建；底层调用生成器的 `scripts/build_docx.py`（内容块契约见 §六）。
   - 脚本只做结构与版式转换，**不改写正文**；需要润色先改 md。
   - 找不到生成器时脚本报「未找到外部 skill，DOCX 导出不可用，md 不受影响」并退出；这是可选依赖缺失，不是插件故障。
5. **核验**：结构检查（标题层级、编号、表格是否被拆行、条款前后一致）＋ 视觉检查（字体是否实际存在、页码、跨页表格）。**没做渲染检查就如实说没做**，不要宣称"已通过格式复核"。
6. **登记**：把 DOCX 记进该卷导读的"正式件"一栏（版本、日期、生成时间、字体组、核验到哪一步），md 与 DOCX 的对应关系写清楚。

### 一页纸（brief，一页，内部传阅）

长文（≥5 节）定稿前另出一页纸（brief）。加载 `longdoc-brief` 技能，产出阅读版（自包含交互 HTML）与传阅版（A4 单页），放该卷 `exports/`。

一页纸是摘要，不是目录，也不是标准说明。默认内部传阅，不随 DOCX/PDF 正式件外发；要外发先改密级与措辞，由人确认。

---

## 三、硬规则

- **不改 DOCX 本身**：要改内容 → 改 md → 重新生成。手改 DOCX 会让 md 与对外件静默分叉，这和"版本混乱"是同一个病。
- **不改内容只排版**时，不要顺手改写正文（技能的排版与改写是两个开关）。
- **不为了"正式"造假**：不虚构发文机关、密级、红头、文号、印章、签发人；企业报告按公文**主体**版式即可。
- **人月/报价/内部判断**：正式件是否包含，按该卷导读的交付等级（L1/L2）执行；L2 先删节再生成。
- **敏感人名**：未经确认的姓名职务不进正式件，用"贵单位领导"等中性称呼。
- **字体**：默认按中文公文常用字体（正文仿宋、一级标题黑体、二级标题楷体、标题方正小标宋）。**必须核对本机与对方环境是否有这些字体**；缺字或替代字体要在交付说明里写明，不能因为 XML 里写了字体名就当成已安装。
- **交付物只给最终 DOCX**，中间稿与 QA 截图留在工作目录，不要一起发。

---

## 四、本机已知情况（2026-10-28 实测）

| 字体 | 本机 | 说明 |
|---|---|---|
| 宋体 / 黑体 | ✅（Songti SC / STHeiti） | 可正常使用 |
| 仿宋 / 楷体 / 方正小标宋 | ❌ | 本机未安装；收文方（Windows 中文环境）通常有 |
| LibreOffice（渲染检查） | ❌ 未安装 | **无法做视觉渲染核验**，只能做结构与字体可用性检查 |

**因此交付说明里必须写**：本地未安装仿宋/楷体/方正小标宋，未做渲染核验；文档中声明的是收文方常见字体，若需本机所见即所得，可改用 宋体/黑体 重新生成一版。

---

## 五、与 PDF 导出的关系

- 正式件主载体是 **DOCX**；对方要求只读件时才转 PDF（`rw_export_pdf` 仍走 md → HTML → PDF 那条老路，和 DOCX 是两条线，**不要用 DOCX 反推 md**）。
- DOCX 与 PDF 并存时，两者都以同一份 md 为源；版本号必须一致。

---

*本方法只依赖 md 与一个可选的 DOCX 生成器契约，不绑定任何特定仓库、内部技能库或个人目录。*

---

## 六、可选桥接：生成器契约与前提

- **生成器契约**：`scripts/build_docx.py <内容块 JSON> <输出 docx> [--overwrite]`；内容块 JSON 形如 `{title, subtitle?, fonts, blocks:[{type, level, text, rows?}]}`。任何满足该契约的实现都能被 `scripts/md2docx.py` 调用。
- **指定位置**：`--skill-dir <目录>` 指向含 `scripts/build_docx.py` 的目录；不传时脚本在常见技能目录里探测。
- **未安装生成器**：`md2docx.py` 报「未找到外部 skill，DOCX 导出不可用，md 不受影响」并以非零码退出；这只影响 DOCX 生成，md 交付不受影响。
- **来源与许可**：生成器由使用者自行提供并自行确认许可；本插件不附带、不再分发任何第三方内容。
- **`human-writing`**：同样可选，只用于改写正文；未安装时直接改 md 即可。
- **不要**在 `SKILL.md` 的 frontmatter 里写 `modelInvocable`——当前加载器把它当废弃字段直接拒收，整个技能会被静默忽略（2026-10-28 在其它技能上踩过，已修）。
