# 02 · KPI 与痛点假设法

> 这是本次调研**最有价值的产出方法**：不靠猜测，而是**用对方的公开动作反推他的考核压力**。
> 铁律：所有结论标注为「**假设**」+「**置信度**」+「**依据**」，未经确认不得当事实使用。

---

## 一、核心逻辑

```
对方"说了什么"（口号）→ 价值低
对方"做了什么"（动作）→ 价值高  ★
```

**四类高价值证据源**（按可信度排序）：

| 证据源 | 为什么有效 | 本次实例 |
|---|---|---|
| **① 上级/治理方的意见** | 外部董事、集团调研提出的意见≈考核要求 | 集团外部董事调研提出"延展数字化业务""强化质量、项目、成本管理" |
| **② 一把手内部会议讲话** | 公开新闻稿中的原话最真实 | "开源节流、精打细算""从紧从严降低支出和成本" |
| **③ 招聘公告** | "紧缺急需岗""放宽比例""整批取消"直接暴露缺口 | 两轮数字化岗位招聘受挫；某岗放宽至 1:3 |
| **④ 采购与招投标记录** | 钱花在哪，优先级就在哪 | 约 6 成院内采购是外协制图；某类项目成交 45 万 |

**辅助证据源**：公开的战略文本（"四化""五大强企"）、对外合作新闻、获奖与标准编制、上市公司/债券披露中的研发费用变化。

## 二、六条通用假设（任何国企客户都可先套用，再验证）

| # | 假设 | 常见依据 | 若成立，材料怎么写 |
|---|---|---|---|
| **1** | 第一 KPI 是**经营指标与战略落地** | 财务数据、战略文本、考核类会议 | 把合作包装为"落实既定战略的成果"，少谈技术 |
| **2** | 关心"**钱花出去有没有效果**" | 成本类讲话、采购价格趋势 | 用可量化口径（工时、成本、通过率）替代功能清单 |
| **3** | 关心"**上级怎么看**" | 上级意见、评优、资质、案例入选 | 提供可上报、可宣传、可获奖的成果形态 |
| **4** | 关心"**人不够、招不到**" | 招聘受挫、外协比例高 | 主张"不增编制提升产能" |
| **5** | 关心"**出错谁负责**" | 平台已上线但无治理制度 | **主动提制度与责任边界**，降低风险感 |
| **6** | 关心"**成果能不能复制/示范**" | 跨区域布局、样板工程 | 提供"先做样板、再复制"的路径 |

## 三、标注规范（强制）

每条假设必须包含五个字段：

```markdown
### 假设 N：<一句话结论>（置信度：高 / 中高 / 中 / 中低）

- **依据**（标注级别与来源）：A 级原文 / B 级报道 / 推断
  - <原文关键句> 来源：<URL>
- **推论**：<由此推出什么>
- **材料含义**：<据此怎么写方案或话术>
- **可提问验证**："<现场可以怎么问，以证实或证伪>"
```

**置信度判定**：

| 置信度 | 判定标准 |
|---|---|
| **高** | ≥2 条独立 A 级证据，且逻辑直接 |
| **中高** | 1 条 A 级 + 1 条合理推断 |
| **中** | 单一证据或较强推断 |
| **中低** | 行业惯例类推，无本方证据 |

## 四、按角色的分层（同一客户，不同人关心不同事）

| 角色 | 关心什么 | 材料侧重 |
|---|---|---|
| **董事长 / 一把手** | 战略落地、经营指标、资产、示范效应、风险 | 一页纸判断 + 合作地图；**不谈技术细节** |
| **分管副总 / 总工** | 技术可行性、责任边界、质量与安全 | 方案架构、边界与制度、验收口径 |
| **执行层（部门/中心）** | 场景、数据、工期、预算、谁配合 | 场景清单、实施路径、分工与接口 |
| **合作方（如设计院）** | 资质、合同主体、专业判断权 | 职责分工与工作界面 |

> **本次经验**：同一天两场会面（设计院院长 + 集团董事长），材料必须**分别重做**，不能一份通用。层级越低越讲"怎么干"，越高越讲"值不值、险不险"。

## 五、从假设到现场：三件套

| 件 | 内容 |
|---|---|
| **开场逐字稿**（60–90 秒） | 用对方的公开动作证明"我做了功课"→ 给出定位 → 提出问题 |
| **必问清单**（5–15 题） | 每题对应一条假设的"验证问法"，按重要性排序 |
| **硬边界**（3–6 条） | 明确"不做什么"，防组织性抵触（如不与对方内部单位竞争） |

**开场结构模板**：
```
① 说出对方已做成的事（证明做功课 + 不重复建设）
② 给出我方定位（互补，而非替代）
③ 提出一个开放式问题（把话语权交给对方）
④ 闭嘴，记录
```

---

## 六、反向使用：把假设当作提问脚本

假设的真正用途**不是预判，而是提问**。每条约 1–2 个验证问题，现场按对方回答实时修正判断。

**示例**：
| 假设 | 验证问法 |
|---|---|
| 关心平台用起来没有 | "平台现在主要服务哪些业务条线？下一步最想往哪扩？" |
| 关心 AI 治理 | "集团对 AI 生成内容的复核责任目前怎么规定？" |
| 关心人才 | "业务条线员工用 AI 的比例大概多少？有统一培训吗？" |
