# examples · 合成示例客户（演示用）

这里是一份**合成数据**的示例客户卷，用来演示 FDE 工作站「导入现有项目 → 看板 → 阶段推进」的完整效果。所有公司名、人名、金额均为虚构，**不含任何真实客户信息**。

## 包含什么

```
research/某集团-20260101/
├── 00-项目档案.md                 项目总入口（导入时用它识别项目名与建议阶段）
├── research/01-事实核查清单.md     证据分级 / KPI 假设 / 未证实清单
└── meeting/某集团面谈Brief.md      会面 Brief（按对象层级组织）
```

## 怎么导入（3 步）

1. 把示例目录复制到你的工作区 `research/` 下（工作区 = 含 `research/` 的目录）：

   ```bash
   cp -R research-workbench-plugin/examples/research/某集团-20260101 <工作区>/research/
   ```

2. 打开 FDE 工作站面板 →「客户」→「导入现有项目」，扫描会把该目录识别为
   **project**（因为存在 `00-项目档案.md`），并根据 `research/`、`meeting/` 目录与
   Brief 文件名给出**建议阶段「会面」**（置信度 medium/high，属推断，不是保证）。

3. 人工确认后点「导入」：客户会出现在看板，历史阶段按 `forced` 记录并写明原因
   （「导入既有项目：历史阶段产物已在磁盘上」），可审计、可回退。

## 预期结果（用来核对导入是否正常）

| 项 | 预期 |
|---|---|
| 项目标题 | `某集团有限公司`（从 `# 项目档案：…` 解析） |
| 目录 | `某集团-20260101` |
| 导入建议阶段 | **会面**（meeting） |
| 门禁状态 | 会面之前的阶段为 forced（历史阶段） |
| 任务/注意力 | 无（示例只提供客户卷） |

## 注意

- 示例只用于演示，**不要**把真实客户的资料拷进这个目录再提交；
- 本目录不属于 npm 发布包（`package.json.files` 不含 `examples/`），只在仓库里供参考；
- 想让示例更完整，可自行补充 `proposal/`、`pilot/` 等目录，导入后的建议阶段会相应变化。
