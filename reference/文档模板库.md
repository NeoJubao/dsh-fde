# 文档模板库

> 各类交付物的章节骨架。直接复制到项目目录后填空。

---

## 一、Brief（现场用，3–5 页）

```markdown
# <客户> <对象> · Brief
> <对象姓名>（职务）｜<日期>｜我方：<我方公司简称>
> 打印带进场。完整论证见《<客户>面谈研判底稿（完整版）》

## 〇、三句话记住这个人
1. <履历特征——决定怎么沟通>
2. <他推动过的具体事——决定不提什么>
3. <当前工作重心——决定从哪切入>

## 一、核心判断（决定怎么谈）
> <一段话结论>
> 所以我方只讲两件事：①…… ②……
> <哪些事一句都不提>

## 二、★ KPI 假设（前三条最关键）
> ⚠️ 均为假设，用于提问验证，不得当事实陈述。
| # | 假设 | 置信度 | 依据 | 若成立，我们怎么说 |
（其余假设折叠为备查表）

## 三、开场逐字稿（60–90 秒）
> "……"

**然后：闭嘴，记录。**

## 四、三个入口
## 五、必问五题
## 六、硬边界（3 条）
## 七、收尾（一定要拿到什么）
## 八、速查数据（备查，不必主动说）
```

---

## 二、合作地图（4–6 页）

```markdown
# <客户> · 合作地图
> 用途：一图说清合作空间、进入通道、落地场景与边界

## 一、合作空间全景
（结构图：客户已有的 / ★合作空间 / 进入通道）
+ 定位一句话

## 二、合作机会矩阵（N 项）
A. <业务方向一> | B. <业务方向二> | C. <业务方向三> | D. 治理与能力方向
（每项：合作机会 / 具体内容 / 对接载体 / 可检查结果 / 卡点）

## 三、进入通道（按优先级）
## 四、★ 边界纪律：我们不做什么
## 五、与客户下属单位的关系设计
## 六、合作地图速查表
## 七、本次会谈目标（对应本图位置）
```

## 三、研判底稿（完整版，8–12 页）

```markdown
# <客户> · 面谈研判底稿（完整版）
> 对象：<姓名>（职务）｜时间：<日期>｜我方：<我方公司简称>

## 一、本次会面的定位与目标
（会面性质判断 + 三个必达目标 + 材料策略）

## 二、对方是谁：公开画像
（履历/任期/特点 + 公开动作轨迹表 + 对沟通方式的含义）

## 三、组织在<议题>上的现状
（已有能力——不得重复建议 / 战略定位 / 财务与投入）

## 四、★ KPI 与痛点假设
（全量假设：依据/推论/含义/可提问验证 + 汇总表）

## 五、合作入口（三条互补路径）
## 六、会谈议程建议（含逐字稿）
## 七、风险与边界（纪律清单）
## 八、待核实事项（C 级清单）
```

## 四、正式方案（建设方案类）

```markdown
# <项目名>建设方案
**（汇报稿）**
| 文件名称 | |
| 文件版本 | V1.0 |
| 编制单位 | |
| 编制日期 | |
| 文件性质 | |

## 摘要
## 一、项目背景与政策依据
## 二、区域现状与需求分析
   ### 2.4 项目基础与实施条件
## 三、建设目标与总体思路
## 四、总体架构
## 五、应用场景建设内容（每场景含：响应缺口/建设内容/数据前提/交付形态/可检查指标/责任边界）
## 六、实施路径
   ### 6.1 总体节奏（阶段 + 周期 + 内容 + 成果 + 决策门）
   ### 6.2 委托方式与实施程序
   ### 6.3 项目组织与职责分工（含工作界面）
   ### 6.4 时序约束
   ### 6.5 推进方式建议
## 七、投资估算与资金安排
## 八、预期成效
## 九、组织保障与风险管理
## 十、交付成果与后续工作
## 附录：主要依据文件
```

**正式化的三条改写原则**：结论→分析、删除内部视角、每项建议留余地。
