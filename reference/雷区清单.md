## A. 主体与归属（后果最严重）

| # | 雷区 | 本次实例 | 防法 |
|---|---|---|---|
| A1 | **用户口述的集团名与实际主体不符** | 用户说某集团下属设计院，实际该院属另一集团 | 地址锚定 + 三链验证；材料中设"归属核对"章节，结论标"待现场确认" |
| A2 | **同园区不同单位误判** | 同一栋楼 9/10 层属另一家单位 | 地址核对到**楼层/单元**；招租公告的出租方要看清 |
| A3 | **简称多义** | "市政规划设计院"可能指两家不同单位 | 用全称核对；列出所有候选与区分依据 |
| A4 | **合作方夸大** | "与某公司签协议"≠"与某集团合作" | 精确到**具体法人主体** |
| A5 | **分页导致漏项** | 成员企业列表有分页 | **核验全部分页**（本次 5 页内容相同，反证无遗漏） |
| A6 | **只看自述不看排除链** | 子公司自称并入某集团 | 必须三链：自述 + 上级 + **排除** |
| A7 | ★**素材目录名 ≠ 目录内容主体** | 做某研究院（代号 X）时按名取用 `research/group/`（实为**某环境投资集团**）、`research/hr/`、`research/news/`（实为**某市政设计研究院**）——三者与该研究院无关，差点被当成本客户素材写进交付 | **取素材前先读 3 行确认主体**；跨客户复用素材时目录须带客户前缀（如 `X/`、`SF/`），不带前缀的共享目录一律先验主体 |

## E. 文档与排版

| # | 雷区 | 防法 |
|---|---|---|

## H. 插件/工作台开发

| # | 雷区 | 后果 | 防法 |
|---|---|---|---|
| H1 | **客户端 apply 未声明 `inject: ['slots','uiWorkspace']`** | `ctx.slots` 为 undefined，面板注册被 try/catch **静默吞掉**——工具正常但面板不出现 | 必须声明 inject；用 `svc('slots')` 取用；不可用时显式报错 |
| H2 | **宿主 apply 未声明 inject** | 同上，`ctx.get('webServer')` 拿到 undefined，路由/工具静默不注册 | 宿主 `inject = ['webServer','tools','systemPrompt','workspaceRegistry']` |
| H3 | **工作区探测依赖 `process.cwd()`** | 拿到的是 DSH 进程目录（如 `~/.dsh/profiles/desktop`），不是会话工作区 | 多策略探测：显式参数 → `workspaceRegistry` → `sessionController` → cwd 上溯 → 常见位置回退 |
| H4 | **改插件源码后以为自动生效** | `patchReload: live` 只监视补丁文件，**不重载插件源码** | 宿主半改动需重启 DSH；客户端半需 `build.mjs` + 重启 |
| H5 | **项目识别条件过严** | 只认 `00-项目档案.md`，导致历史目录被完全忽略 | 双条件：有档案=正式立项；有 raw/research/meeting/proposal=历史目录（标记未建档） |
| H6 | **静态检查不覆盖关键约束** | 缺陷在验证中溜过（本次 inject 坑即是） | 把每条踩过的坑转成一条静态检查项 |
