# PDF 兼容性与"微信打开乱码"排查记录

> 建立于 2026-10-13。用于下次遇到"PDF 发出去显示乱码"时快速定位。

---

## 一、可直接复用的验证命令

```bash
# 1) 字体是否嵌入（emb 必须为 yes）
pdffonts file.pdf

# 2) 文本能否提取（能提取 = 文字是真文字，不是图片/乱码）
pdftotext -f 1 -l 1 file.pdf - | head -20

# 3) 文件完整性
python3 -c "
d=open('file.pdf','rb').read()
print('头:', d[:8]); print('EOF 标记:', b'%%EOF' in d[-100:]); print('大小:', len(d))
"
```

## 二、实测对比（同一份中文 md）

| 生成方式 | 字体类型 | 嵌入 | 文本可提取 | 文件大小 | 结论 |
|---|---|---|---|---|---|
| **WeasyPrint** | **CID Type 0C (OT)** | yes | ✅ 正常 | **534 KB** | **推荐** |
| Chrome headless `--print-to-pdf` | **Type 3**（用绘图指令画字形） | yes | ✅（依赖 ToUnicode，兼容性差） | **1024 KB** | ❌ 不推荐用于微信传输 |

**关键差异**：
- WeasyPrint 输出**标准 CID Type 0C 字体**，是 PDF 规范里的正规做法，绝大多数阅读器兼容；
- Chrome headless 把字形嵌成 **Type 3**（每个字形是一段绘图指令），**文件大一倍、兼容性差**，在部分移动端阅读器上易崩或显示异常。

样本已移出仓库：本记录原来留存 2 个中文 PDF 样本（WeasyPrint / Chrome headless，约 1.53 MiB），已从插件目录移出。按上文三条命令对任意中文 md 重新生成 PDF，即可复现同一组对比（字体类型、嵌入、可提取性、体积）。

## 三、"微信打开乱码"的分层排查

字体已嵌入且文本可提取时，**问题不在 PDF 生成端**。按下列顺序排查：

| 层级 | 现象 | 处理 |
|---|---|---|
| **① 传输** | 微信把文件当"预览"压缩/改名，或传输中断 | 让对方**另存为**原始文件；确认文件名后缀仍是 `.pdf` |
| **② 客户端** | 微信内置预览器对 CID Type 0C 子集渲染异常 | 让对方点「**用其他应用打开**」（WPS / Adobe / 系统预览） |
| **③ 系统** | 接收端缺中文字体（极少见，因字体已嵌入） | 换用系统阅读器 |
| **④ 生成端** | 字体未嵌入 / 用了 Type 3 | 用 `pdffonts` + `pdftotext` 验证；改用 WeasyPrint |

---

## 四、给"要用微信发"的场景的三条建议

1. **首选 md 或纯文本**：微信里直接粘贴文字最稳，手机端阅读体验也好；
2. **要发文件就发 PDF**（不是图片），且提醒对方「**用其他应用打开**」；
3. **对方只看内容、不需要排版** → 直接把 md 正文粘贴过去，链接与表格降级为纯文本即可。

> **原则：md 是资产，PDF 是快照。只有在"要打印/要递交"时才导出 PDF。**
